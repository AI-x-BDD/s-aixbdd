# 依內容設計影片的製作流程

本流程供新影片、整體美術改版與設計評審使用。操作指令見 [README](README.md)。只重建已定版的來源時，直接依 README 操作；重建不代表重新通過美術驗收。

狀態：已完成 CH2 新流程測試片的候選比較、使用者方向確認、獨立正式輸出及靜態畫格複查。AI 未直接聽看全片，聲畫舒適度與使用者最終驗收仍待完成；不得宣稱流程已完整通過美術品質驗收。CH2 的舊成片不是本流程的驗收成果。

## 執行範圍與紀錄

開始前確認使用者要的是流程修改、設計提案、正式製作或既有成片修正。只執行已授權的範圍。修改流程的授權不包含製作影片；提案授權包含獨立候選預覽，不包含覆寫正式來源或成片。曾製作過同一影片，不表示後續流程修改或提案也獲准重製。已有涵蓋正式製作的授權時，方向確認後持續完成工作；只有提案授權時，交付推薦與預覽並明確詢問是否進入正式製作。

從影片設定找到外部來源與既有決策；尚無設定時使用使用者指定的來源目錄。每支影片的設計紀錄放在該來源的 `製作紀錄/設計/`，預覽與衍生檔放在該片 build 下。通用流程留在 videos，個案內容與配色留在該片紀錄。

| 紀錄 | 用途 |
| --- | --- |
| `設計依據.md` | 內容依據、理解目標、限制與工具能力 |
| `視聽提案.md` | 候選方案、預覽連結、比較、推薦與使用者確認 |
| `分鏡.md` | 逐幕製作 brief、色彩角色、聲畫時間與交接 |
| `美術評審.md` | 實際檢視證據、問題、修正與複查結果 |
| `交付狀態.md` | 目前階段、已完成、待確認與下一步 |

紀錄可引用既有文件，避免複製內容。每次交接更新階段與下一步；需要使用者選擇時，展示可審閱的成果、推薦與明確確認問題。未完成項目如實列出。

Skill 已安裝、已閱讀、規範已套用、成果已驗證是不同狀態。`美術評審.md` 分別記錄內容適配、可讀性、結構、focus、聲畫節奏的證據與結果（通過／不通過／未驗證）；交付文字、預覽頁與交接紀錄須一致。不能以「有使用 Skill」或技術檢查通過宣稱整體設計已達標。

| 視聽方向與具體構圖 | [.agents/skills/presentation-design-editorial/SKILL.md](.agents/skills/presentation-design-editorial/SKILL.md) | 色彩階層與角色、排印、構圖、視覺識別與反模式檢查；確切色相選擇與內容適配依本流程第 1、2 階段補足 |

兩份 presentation-design 的 upstream name 相同：`presentation-design-editorial/` 是 blisse-code 的美術設計版，`presentation-design/` 是 jwynia 的診斷版。保留原始 frontmatter；目錄別名不會消除名稱呼叫的歧義。委派時寫出路徑與責任並明確讀檔，不能只用同名指令。第三方原文與授權保持原樣，來源與固定版本見 [.agents/skills/來源.json](.agents/skills/來源.json)。各 agent 的自動掃描範圍不同，本流程不依賴自動發現；Claude Code 也由 WORKFLOW 的路徑讀取這些檔案。

適配時以使用者需求與本流程為準：storyboard 的課程媒體分類需轉成影片中的可播放畫面，不產出影片外的互動測驗；簡報 Skill 的比例、固定版型與色彩心理描述是設計參考，須依內容驗證。署名、logo、比較偏向及既有風格延續，只在符合本片要求時採用。其餘已裝 Skill 可依實際需要補充，不取代上表的產出與評審。

editorial Skill 的 Color Foundation 規範階層、對比與用途，不是自動依題材選出色相的工具；流程主代理負責補齊選擇、比較與評審，不能把載入該 Skill 當成主題配色已完成。

## 1. 建立內容與觀眾的設計依據

讀取說明材料、來源證據、旁白與既有決策，填寫 `設計依據.md`：

- 主題、觀眾背景、觀看情境與觀看後應理解或採取的行動。
- 每段的核心訊息、結構／因果／變化／對比，以及需要的理解時間。
- 整體希望傳達的感受與段落情緒變化，逐項說明與內容的關係。
- 內容或品牌是否限定色彩；來源中的實物、環境、分類慣例或參考視覺是否提供選色線索。區分來源事實、觀眾假設與美術裁量，沒有指定色相時如實記錄，不捏造內容必然要求某種顏色。
- 顏色要承擔哪些訊息，哪些區別已有位置、形狀或文字承擔；列出觀眾可能帶入的既有色彩慣例與誤讀風險，風險須用實際畫面核對，不先當成事實。
- 已確認與可調整的範圍：內容、旁白、片長、品牌、素材、尺寸及聲音。
- 可用製作工具的實際能力；聲音來源、配音參數與未知事項。

只詢問無法從現有材料得知且影響設計的資訊。由 AI 承擔呈現與美術判斷，不要求使用者先提供設計術語。

完成條件：所有段落都有可追溯的理解目標，設計選擇所需的限制與未知事項已列出。

## 2. 根據內容提出整套視聽方向

依 Skill 分工提出至少兩套具有實質差異的候選方向，寫入 `視聽提案.md`。每套均包含：

製作候選預覽前，核對設計所需的 renderer 與聲音能力。尚無法呈現的動態、無法聽審的聲音或未確定的正式配音參數，逐項在提案與預覽旁標示「未呈現／未驗證」、原因與下一步；不能用靜態淡化假裝展示了連續動態。

| 面向 | 必交內容 |
| --- | --- |
| Color scheme | 主背景、次背景、主次文字、主體、強調與必要分類色的色碼、用途和搭配理由；連回主題、觀眾與希望傳達的感受 |
| 跨幕色彩 | 哪些角色固定，何時變換冷暖、明暗或背景，以及如何支持敘事；分類色與 focus 色語意須能區分 |
| 畫面呈現 | 各段用圖解、文字、實際畫面、比喻或變化動畫的理由，以及可能誤解 |
| 畫面結構 | 資訊分組、排印、主次、留白、閱讀順序與跨幕連續性 |
| Focus | 觀眾先看什麼、接著看什麼；以尺寸、位置、對比、揭露或動態配合當下解說，並保留辨識所需脈絡 |
| 節奏與聲音 | 段落快慢、停留與轉折；旁白密度、語速及停頓如何配合畫面，哪些時刻需要降低資訊量 |

每個新主題重新推導色彩與美術方向。石墨黑、暖白、亮藍是 CH2 個案，不是通用預設；「科技用藍色」之類的主題標籤不足以構成理由。沿用配色時也需說明適配依據。

### 先形成選擇依據，再製作與比較

在填色碼與套構圖前，把內容需求轉成可觀察的設計條件，寫入 `視聽提案.md`。例如「說明抽出檔案後仍須接回 SOP」需要可辨識的原文件、外部檔案和回接關係；這能約束結構與焦點，不能直接推論綠色或紫色最適合。

候選的色彩與結構分開比較，不把構圖的優勢當成色系的優勢。記錄下列項目，可與既有提案表合併：

| 項目 | 必交證據 |
| --- | --- |
| 內容需求 | 來源段落／片語、理解目標與希望形成的觀看感受；推測標為假設 |
| 色彩候選 | 比較的色系及其明暗、冷暖、彩度與角色關係；依據來自內容線索、品牌、具名參考或美術裁量。參考須能定位，不臨時杜撰 |
| 結構候選 | 資訊關係如何映射到分組、路徑、主次與閱讀順序；預期改善什麼、可能造成什麼誤讀 |
| 實際比較 | 預覽檔與畫格／時間點、觀察到的差異、保留或淘汰理由；至少檢查一項推薦案可能失敗的情況，例如密集文字、焦點切換或分類混淆 |
| 結論 | 色彩與結構各自的推薦、取捨、證據強度及未驗證事項；多案同樣適合時明說，不能製造唯一正解 |

選色不以輪換色系或避開曾用顏色為目標；比較應包含能檢驗當前選色假設的替代方案，而非只改色碼。色彩心理描述只可作待驗證假設。若內容沒有支持特定色相，明列為美術裁量，依實際畫面的氣質、層級與閱讀負荷比較；不能只寫「安定、專業、科技」就算內容適配完成，也不要求證明某個色相是唯一正解。

對同一組代表內容製作候選方向的實際畫面，涵蓋主體、文字、背景與 focus 狀態；同時提供跨幕縮圖及一段有聲的節奏預覽。配色需在相同構圖上另作對照，以便判斷色彩效果；完整方案仍可有不同構圖。只有色票、風格名稱或文字描述，視為提案未完成。

比較須對應聲稱的效果：若要判斷色相，保持構圖、文字、焦點狀態及相近明暗／彩度條件；若同時由淺底改深底、改色相與強調色，只能說是整套色彩方案的差異，不能據此把效果歸因於單一色相。有無法控制的差異時列出限制，補做足以支持推薦的對照。

### 推薦前的適配檢查

由評審者先讀內容需求，再看實際預覽，逐項在 `美術評審.md` 記錄：需求、候選差異、觀察位置、可能反例、結論。評審者可為主代理；有委派時明列對方實際看過的材料。不能只核對提案是否填滿或重述設計者的理由。

- **色彩適配**：選色依據及美術裁量清楚；同構圖比較支持所宣稱的效果；分類、焦點與主題氣質無衝突。文字對比另列為可讀性結果，不充當色系適配證據。
- **結構適配**：圖像關係準確表達來源；閱讀順序與解說一致；比較結果能解釋推薦結構的優勢或取捨。
- **focus 與節奏**：在實際代表狀態／片段檢查焦點切換、理解時間與保留脈絡；沒聽過就不能判定聲畫配合通過。

色彩或結構的必交依據缺失、尚未檢視實際比較、或觀察推翻原理由時，退回本階段補設計與比較，不提出整套採用推薦、不請使用者選版。美術裁量已揭露且比較充分，不因缺少唯一色相而退回。部分通過須指明面向；聲音等受能力限制的未驗證項目可依下列部分預覽規則交付，但不能拿使用者確認代替 AI 應完成的適配檢查。

新片可使用暫定旁白或預覽語音，標明與正式配音的差異。依內容選擇資訊密集或有轉折的代表段，不固定抽取 CH2 的幕號。候選原稿、隔離設定與建置指令依 [README 的候選方案建置](README.md#候選方案建置) 操作，不使用只重建舊樣稿的 visual-samples 當作產生新提案。

完成條件：AI 已檢視實際預覽、比較各方案的內容適配與取捨並修正問題，提出一套推薦及理由，再請使用者確認。關鍵動態或聽看尚未驗證時，以「部分預覽，待驗證」交付，明確列出需確認的範圍，不標為完整視聽方向已驗證。方向未確認時，停在提案階段；不擅自套用正式全片。

## 3. 逐幕設計與聲畫共同定版

把已確認方向與設計依據交給對應 Skill，為每幕寫出 `分鏡.md`，至少包含：

- 核心訊息及來源、呈現方法與理由；關鍵段落保留替代做法及推薦理由。
- 起始／展開／結束畫面、具體物件與內容、構圖和色彩角色。
- focus 對象、揭露與移動順序、保留脈絡的方法及語意轉折。
- 對應旁白片語、預計或實際起訖、停留與過渡時間；跨幕延續物件的狀態。
- 製作工具與能力適配；無法實現的項目、替代方案與取捨。

新影片在正式配音前，以暫定旁白與動態預覽共同調整稿件密度、語速、停頓及畫面時間。語速數字只能作為估算；須實際聽看，確認圖文可讀且理解有時間落點，再交付正式配音。

已有確認的旁白、正式音檔或片長時，先在該限制內設計。若確需改稿、重配或更動片長，展示具體原因、影響與替代方案，取得確認後才修改。語音與時間整合由本流程負責，不能宣稱某支設計 Skill 已涵蓋完整配音導演能力。

完成條件：每幕都有可直接製作的 brief，旁白與畫面時間可對應，所有需變更的既有決定已取得確認。無法實際聽看時，保留未驗證標記並交代補驗方式，不宣稱聲畫已共同定版。

## 4. 正式製作與技術驗證

在已授權的製作範圍內，依確認的分鏡製作、對齊、建置及預覽，操作方式見 README。原始素材的保護、對齊雜湊及技術檢查持續生效。

字幕目前依使用者指示採燒錄，之後收到變更指示再調整。保留 SRT／VTT 來源供修改，交付播放與下載都指向燒錄版；既有 renderer 產生字幕軌時還須完成燒錄步驟，不能直接當成交付版。字幕排版須避開內容，必要時保留獨立字幕帶；以實際畫格確認文字可見、未被裁切或遮擋，另確認片長與音訊未被意外改動。CH2 測試片的做法見 `projects/ch2-workflow-test/finish.py` 與 `burn_subtitles.py`。

先查核目前 renderer 能力。現行語意 SVG renderer 以靜態狀態與交叉淡化為主；設計若需要物件變形、鏡頭或連續移動，不可用輪流變色代替後宣稱已完成。提出工具擴充或可實現的等效方案，涉及既有確認方向的改變時先取得確認。

完成條件：正式輸出通過適用的技術檢查，預覽播放同一成片；尚未完成美術評審時，狀態標為「技術通過，待美術評審」。

## 5. AI 全片美術評審與交付

AI 先看跨幕縮圖，再從正式 MP4 檢視每幕所有有意義的狀態與過渡，並實際聽看全片。把檔案／時間點、觀察、判斷理由、修正與複查結果記在 `美術評審.md`：

| 檢查面向 | 通過的依據 |
| --- | --- |
| 內容適配 | 配色、圖像或比喻、構圖與動態能追溯到理解目標，不扭曲來源 |
| 色彩適配 | 複核選色依據與實際比較；領域慣例、主題氣質、分類與 focus 無已確認但未處理的衝突；美術裁量及未驗證假設另列 |
| 色彩可讀性 | 實際文字與背景組合可讀；必要區別也有文字或形狀線索；focus 不與分類色混淆 |
| 結構與變化 | 每幕有清楚的視覺起點與閱讀順序；相似版面有內容理由，系列畫面能辨識各自訊息 |
| Focus | 當下解說與視覺對象對應，觀眾能跟上，脈絡不被過度淡化或遮蓋 |
| 節奏與聲音 | 有時間閱讀及理解，語速、停頓、畫面變化與轉折配合，沒有為追動畫壓縮理解時間 |
| 整體一致性 | 色彩角色、排印、物件與動態語言一致，變化有敘事目的 |

可讀性應檢查實際色碼的文字／背景對比，並在最終觀看尺寸與編碼畫面確認；對比數值通過只證明其中一項條件。依內容判斷是否需要重排或減量，不能以固定留白比例、元素數或版型輪替代替美術判斷。
