# 固定測試輸入

共同條件：使用指定 Skill；一律繁體中文；只產出訊息或審查結果，不建立 commit、不修改環境。每題獨立判斷。沒有使用者確認閘門的預先回覆；若有問題只記錄問題，不猜使用者回答。

## S1：專案規則與效能（回歸）

在指定 fixture 根據 staged diff 撰寫訊息。這次改動只為降低中間 list 的記憶體配置，輸入輸出不變；未追蹤檔留待下次。請自行讀取所需專案規則。

判準：perf；scope 遵守 CONTRIBUTING.md 的 engine.py；繁體中文；不包含 scratch.txt；HEAD、index、檔案不變。

## S2：合法 footer 審查

只審查以下訊息是否符合 CC 1.0.0；無額外團隊規則。變更確實移除公開設定鍵，不檢查 repository diff：

```text
refactor(config): 移除過時的 timeout 設定鍵

BREAKING-CHANGE: 請改用 requestTimeout。
```

判準：合法，BREAKING-CHANGE 是 BREAKING CHANGE 的同義 footer；不強制改成 !。

## S3：不合法 footer 審查

只審查以下訊息是否符合 CC 1.0.0；無額外團隊規則。變更確實破壞公開設定，不檢查 repository diff：

```text
refactor(config): 移除過時的 retries 設定鍵

breaking change: 請改用 retryLimit。
```

判準：小寫 breaking change 不合規，提供 ! 或大寫 footer 修正版；不聲稱所有 type 必須小寫。

## S4：混合目的（回歸）

只根據完整變更摘要給 commit 草稿，不操作 Git：原本沒有訂閱暫停功能，現在新增；同時把不相關的既有下載按鈕顏色修回設計稿要求。沒有團隊規則。

判準：建議拆成 feat 與 fix；CSS 修錯不用 style；不執行 stage 或 commit。

## S5：純重構（回歸）

只根據完整變更摘要給 commit 草稿，不操作 Git：把帳單金額計算的重複分支抽成私有函式；輸入輸出、公開 API、效能及錯誤行為均不變。沒有團隊規則。

判準：refactor；不加 breaking 標記；不捏造 feat 或 fix。
