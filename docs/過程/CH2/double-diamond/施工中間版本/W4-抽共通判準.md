# SOP

## Phase 1 -- 理解與分析

1. `READ` 使用者需求及其提供的情境、證據、方案與驗證結果，建立「需求輸入」。
2. `THINK` 依「需求輸入」辨識用途與所需主題，建立「任務範圍」，保留全部適用用途。
3. `READ` 讀取 `rules/雙鑽石判準-格式規範.md` 的所有 Rule，建立「雙鑽石判準檢查清單」。
4. `THINK` 依「雙鑽石判準檢查清單」形成雙鑽石模型與方法關係判準，建立「模型與方法判準」。
5. `READ` 「任務範圍」涉及需求分析、階段判定、研究收斂、例外判斷，或其他用途需要判斷不確定性及流程適用性時，讀取 `rules/任務分流-格式規範.md` 的所有 Rule，建立「任務分流檢查清單」。
6. `THINK` 依「任務分流檢查清單」判斷任務的不確定性與適用路徑，建立「分流判斷」。
7. `READ` 「任務範圍」涉及需求分析、Problem Statement／Design Brief／Success Criteria、方案發展與驗證、Decision Gate，或其他用途需要說明各階段實際做法時，讀取 `rules/需求分析-格式規範.md` 的所有 Rule，建立「需求分析檢查清單」。
8. `THINK` 依「需求分析檢查清單」分析需求或說明各階段實際做法，建立「需求分析判斷」。
9. `READ` 需要案例時，讀取 `references/cases.md` 的相關案例與參考資料，建立「案例參考」。
10. `THINK` 依「需求輸入」、「任務範圍」、「模型與方法判準」，以及本次形成的「分流判斷」、「需求分析判斷」與「案例參考」，並依「雙鑽石判準檢查清單」與已載入的「任務分流檢查清單」與「需求分析檢查清單」形成「分析結果」。

完成條件：已取得任務範圍及依適用判準形成的分析結果。

## Phase 2 -- 產出與檢查

1. `WRITE` 依需求、分析結果與本次適用的「模型與方法判準」、「分流判斷」、「需求分析判斷」，及本次已載入的「任務分流檢查清單」與「需求分析檢查清單」，形成「回覆草稿」。
2. `CHECK` 依本次已載入的「任務分流檢查清單」與「需求分析檢查清單」及「雙鑽石判準檢查清單」核對草稿符合需求與所有適用內文約束且已使用前述判準；缺少主題返回 Phase 1 步驟 2，分析錯誤返回 Phase 1 步驟 7，其餘返回步驟 1。
3. `WRITE` 交付已通過檢查的回覆。

完成條件：回覆涵蓋需求、通過適用判準並已交付。
