# 原輸入

請說明 Double Diamond 的兩次發散收斂、四個 Design Principles，以及它與 Design Thinking、Agile 的關係。Develop 是開始寫程式、Deliver 就是 deploy 嗎？流程可以回頭嗎？

# 原始回答

Double Diamond 是 Design Council 用來描述設計流程的模型，重點是避免太早認定問題，也避免太早愛上某個解法。它分成兩個空間、四個階段：

- 第一鑽石是 Problem Space，目標是「找對事情」（Design the right thing）。
  - Discover：發散探索，透過觀察、訪談、資料等證據，挑戰「我們以為的問題」。
  - Define：收斂整理證據，決定真正要解的問題、對象、限制與成功條件。
- 第二鑽石是 Solution Space，目標是「把事情做好」（Design the thing right）。
  - Develop：發散發展多個可能方案，並用 sketch、prototype、技術 spike 或小型 PoC 試探風險。
  - Deliver：收斂驗證方案，透過任務測試、錯誤率、效能、成本或其他適用證據淘汰、改善並留下可行方案，之後仍要持續量測。

Design Council 的四個 Design Principles 是：

1. Put people first：以人為本。
2. Communicate visually and inclusively：以視覺化且包容的方式溝通。
3. Collaborate and co-create：協作與共創。
4. Iterate, iterate, iterate：持續迭代。

這些原則與四階段是設計工作的指引；Double Diamond 是流程模型，不是規格，也不是每次都必須照固定步驟執行的官方強制 SOP。

Design Thinking 是較大的思考哲學與設計脈絡；Double Diamond 是把其中的發散與收斂，以及「找對事情、把事情做好」視覺化的一種方法。IDEO 所說的 Creating choices → Making choices，也可用來理解發散 → 收斂。兩者不是互斥方法，也不應把 Double Diamond 說成 Design Thinking 的全部。

Agile 主要回答「怎麼快速、持續把東西做好」，Double Diamond 主要回答「應該做什麼」。實務上可以把 Discover／Define 的學習帶進 Product Backlog，在 Develop／Deliver 中以 Sprint 建立、測試與量測，再依回饋重新 Discover。這是可採用的實務接法，不是官方唯一順序。

因此，Develop 不等於開始寫正式程式。寫程式可能是其中一種驗證方式，但 Develop 的核心是展開不同可能方案，先用便宜的原型或技術試驗回答最大的未知。Deliver 也不等於 deploy；deploy 只是可能的交付動作，Deliver 還包括測試、淘汰、改善、確認結果，以及上線後持續量測。

流程可以回頭，而且本來就不是線性的 Waterfall。若 prototype 或上線後資料顯示真正障礙不同，或原本的 Problem Statement 不成立，就可以回到 Discover／Define；若方案驗證失敗，也可以回到 Develop 重新探索。新的證據應該能改變原本的判斷。
