## S8

### 原輸入

請說明 Double Diamond 的兩次發散收斂、四個 Design Principles，以及它與 Design Thinking、Agile 的關係。Develop 是開始寫程式、Deliver 就是 deploy 嗎？流程可以回頭嗎？

### 原始回答

```text
Double Diamond 是描述設計流程的模型，不是固定的逐步 SOP；它用兩顆鑽石表示兩次發散與收斂：

第一鑽石是 Problem Space，目標是 Design the right thing：
- Discover：發散探索，挑戰原本以為的問題，從使用者、行為、商業與技術資料找未知與證據。
- Define：收斂，把 Evidence → Pattern → Insight → Problem → Priority，形成真正要解的 Problem Statement。

第二鑽石是 Solution Space，目標是 Design the thing right：
- Develop：發散多種可能方案，用 sketch、wireframe、prototype、技術 spike 或小型 PoC 便宜地驗證風險。
- Deliver：收斂，用使用者任務、錯誤率、效能、成本與維護等證據測試、淘汰與改善候選方案，留下可行方案。

四個 Design Principles 是：
1. Put people first：把人與其需求放在中心。
2. Communicate visually and inclusively：用視覺方式並以包容的方式溝通。
3. Collaborate and co-create：協作並共同創造。
4. Iterate, iterate, iterate：持續迭代。

Develop 不等於開始寫正式程式。寫 code 可以是技術 spike 或 PoC，但 Develop 的重點是先展開多個可能方案並回答未知問題。Deliver 也不等於 deploy；它是用測試與證據驗證、淘汰、改善並選定方案。Production 上線後還要 Measure → Learn，必要時重新 Discover／Define／Develop。

Double Diamond 與 Design Thinking：Design Thinking 是較大的設計思考哲學與方法脈絡；Double Diamond 是把設計流程視覺化的一種模型。IDEO 的 Creating choices → Making choices，也對應發散與收斂。

Double Diamond 與 Agile：Double Diamond 主要回答「應該做什麼」，Agile 主要回答「如何快速、持續把東西做好」。常見接法是 Discover／Define 形成 Product Backlog，Develop／Deliver 和 Sprint、回饋迴圈結合，再依新學習回到前面的階段。

流程可以回頭。官方模型不是線性的；在 Deliver 或 production measure 後發現新證據，可以回到 Discover 或 Define，也可以在 Develop 重新比較方案。兩顆鑽石不是做完一輪就永遠結束。
```
