# CH2 說明影片製作流程與初版交付

日期：2026-10-17。

## 初版狀態

使用者確認影片長度、文字、聲音與畫面切換基本上 OK；紅框 focus 有做到，文字與內容搭配可接受。目前定位為可運作的影片草稿，尚待正式配音與美術設計。初版為九段、116.28 秒，節奏參考快照位於 `版本/20261017-節奏與旁白參考/`。

## 從無到有的流程

1. 確定主軸與限制：90–120 秒，介紹自己做出的 Skill Engineering、如何調度 primitives，以及三支技能的優化前後差異。
2. 對照專案內 Skills 與前後比較紀錄，整理證據引用。以實作的五支 Form、三支 Deriver 呈現分工；Description 作為整體一部分，不插入額外增加的沿革。
3. 將旁白、場景、畫面說明、證據引用及 focus 定位整理為 `製作內容.json`，以 SVG 製作畫面。以原始設定作為唯一修改入口，避免直接修改建置產物。
4. 依使用者回饋移除多餘的道館、帳號標籤與施工驗證敘述；調整生硬用字，讓三支技能差異保持平衡。
5. 將原先分散的臨時製作流程整理成 `videos/` 獨立工具專案。原始素材持續留在外層章節目錄，工具讀取外部素材，衍生檔寫入 `videos/build/`；以可設定的來源路徑支援日後獨立複製。
6. 使用 Meijia 系統語音逐段生成音訊，依實測長度切換畫面；裁去段尾多餘靜音，不填充無聲停留。由 SVG 生成 PNG，產生時間軸、估時字幕、紅框 focus、HTML 預覽與 MP4。
7. 查閱 Reynolds、Duarte 與 Assertion-Evidence 的簡報方法，重寫為問題開場、分工圖與完整委派，再接三支技能前後對照。來源與採用方式見 `簡報敘事調整.md`。
8. 完整 render 後檢查片長、靜音、來源檔未被建置改動；檢視生成圖稿，於瀏覽器驗證播放與切換。獨立複製工具的重建驗證使用改寫前版本，詳見 `videos/HANDOFF.md`。
9. 使用者看到新版後肯定節奏與旁白呈現，保存原始 JSON、九張圖稿、時間軸與節奏檢查作參考，再整理配音文字與後續工作。

## 如何重現

從專案根目錄執行：

```sh
make -C videos setup
make -C videos check
make -C videos render
make -C videos preview
```

最新輸出為 `videos/build/ch2-skill-engineering/`，預覽為 <http://127.0.0.1:60070/預覽.html>。已有伺服器時，render 完重新整理即可。

本素材目錄頂層原有 MP4、MP3、HTML、字幕及時間軸是較早的歷史產物，保留作紀錄，不是最新初版；60069 亦曾提供舊預覽。辨識目前初版：116 秒、開場「技能越改越難維護？」。未來應以 videos/build 產物及來源 JSON 為準。

## 下一階段一：正式配音與對齊

- 提供 `正式配音/完整旁白.txt` 與九份分段 TXT，供使用者在 ElevenLabs 產生配音。詳細畫面對應及目前參考秒數見該目錄 README。
- 正式音檔回來後，實作外部音檔載入，量測每段長度，再對齊畫面、字幕及 focus。現有字幕與 focus 仍為比例估時，不能當成正式音檔的準確時間。
- 以已確認的緊湊節奏為基準，檢查英文發音與段落連接，總長仍不超過 120 秒。

## 下一階段二：美術與視覺呈現

- 保留已確認的文字、敘事、分鏡與節奏作起點，優先探索整體色系、字體層級、圖形語言、構圖、點綴與轉場。
- 使用者認為目前配色及積木式排列只達到基礎可運作程度；下一輪需提出有辨識度、能吸引注意的視覺方向，先用代表畫面比較，再套用全片。
- 紅框 focus 已獲肯定，保留引導觀眾注意的功能；外觀可配合新風格調整。不重新加入多餘頁角標籤，也不為裝飾增加停頓。

以上兩階段尚未完成；本次先保存初版與交接，不自行生成 ElevenLabs 配音或改做新美術版本。
