# 共同評分準則

六次從相同 commit、相同模型設定、獨立 session/worktree 執行 Skill Engineering；長短各三次。總指揮依相同規則審查根因與藍圖，不提供保留測試的答案。

首度交付候選版本先封存，再由全新對話測試兩項既有缺漏；不向執行者提供預期答案：

1. 團隊流程檢查：是否檢查 Feature Flag 清理；無資料可標待確認，不可直接漏掉。
2. production hotfix 規劃：是否提供具體 PR／技術、各 PR 安全進 main 理由、含 review 的 branch 存活時間；並核對應載入規劃規則。

每項記錄實際輸入、原始輸出、工具載入痕跡、判斷及檔案雜湊。分開記錄首度表現與回修結果，不把回修覆蓋成首次成功。另記 Skill Engineering 是否偵測及處理自行驗收失敗。

共同工程閘門：根因必須有現有文件或實跑證據，推測明示；用途和正確規則不得刪失；藍圖有逐項追溯、READ 觸發、載入後使用與 CHECK，不任意湊檔；兩側實體同步，實跑不能以靜態檢查冒充。
