  ### S4：團隊是否符合 TBD

  目前不符合。

  • 核心違反：長期 develop、release-next 若承載共同開發，就是長期開發分支。
  • 核心違反：若紅的是 main CI，仍繼續開發違反保持 main 可工作的要求；應立即修復或 revert。
  • 整合阻礙：review 等待兩天也算 branch 壽命，難以達成 DORA 每天整合的目標；不能只看實作花多久。

  先建立自動 build／test、快速 CI 與必要的合併檢查，落實 broken main 優先修復，縮短 review 等待並練習切小，再逐步退出長期開發分支。

  仍需確認每天整合頻率、active branches 數量、CI 回饋時間、是否靠 code freeze，以及 flag 清理情況。若 release-next 僅維護已發布版本，應按 release branch 用途另行判斷。
