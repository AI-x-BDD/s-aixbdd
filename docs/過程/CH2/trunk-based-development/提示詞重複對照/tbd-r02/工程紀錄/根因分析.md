觀察：現況主檔混合用途、來源分級、流程、決策樹、技巧、錯誤模式與檢查；唯一引用是 `references/cases.md`，沒有 RuleFile 或具名載入結果。這是可直接核對的結構改善需求，不假稱已有使用者行為失敗紀錄。

## 3. 落差

| 驗收條件 | 預期 | 實際 | 證據 |
| -------- | ---- | ---- | ---- |
| E1–E3 | 流程與規則有可查核的模組化關係 | 觀察：無 `# SOP`；規則全在主檔；沒有 RuleFile、具名清單與 READ→使用→CHECK 鏈 | 原主檔各節；audit 的 SOP001 |
| E4 | 正常小修正建議 | 觀察：S1 的 TBD 判準通過，但把輸入「少一個空格」誤述成「多餘空格」 | 原始輸出一的 PR 1 |
| E5 | 團隊選擇與流程適用範圍一致 | 觀察：主檔「團隊自行決定」允許 direct push，但「規劃需求的流程」每個小變更固定開 branch 並 PR/review；S2 同時說 direct push 自由、又要求不能繞過 review | 原主檔上述兩節；原始輸出二 |

分類：E1–E3 是已證實的結構改善缺口；PR／review 是文字適用範圍張力，不宣稱 direct push 本身失效。S1 空格方向是實測用詞錯誤，無證據定位為 TBD 規則缺陷，不因此新增規則。模組化會提升答題正確率、減少成本或穩定性等均為待驗證推測，本次不承諾。
