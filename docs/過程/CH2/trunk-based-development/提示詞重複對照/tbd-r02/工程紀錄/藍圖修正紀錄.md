## 第二版具體修正

1. P1-4 READ 明列所有 branch／PR／團隊 workflow 審查，包括未點名技巧的一般審查；規劃與技巧選擇同樣載入拆分清單。純方法比較可略過。
2. 兩份 READ 均移至分析前：P1-3 共同規則、P1-4 適用拆分規則、P1-5 使用具名清單分析，再 P1-7 形成方案或審查草稿。
3. P1-8 先核對應載清單是否齊全；漏載回 READ 並重做後續分析／草稿，再逐條檢查內容。完成條件包含使用前已載入，不只對已有清單自我檢查。
4. C6／主幹 Rule 3 補回原有 merge 後刪 branch 的強烈建議與未刪模式；C21 僅表達流程順序。兩者各自單一存放位置，不改建議強度。
5. 藍圖第 5 節新增用途→原規則→READ→第一次使用→CHECK 矩陣，核對六個 workflow 面向、六個送出問題及所有 description 用途。Flag、API 相容、抽象替換、release 修復方向均可由審查路徑到達。
6. W1 改為同一個分析 THINK 暫存兩主題；W2/W3 定位同一步驟、分別抽取拆分與共同規則，並同時交付 READ、分析／草稿使用及 CHECK 的完整 After。保留胖 SOP 先寫入的施工要求。
7. 增列 S5–S8 補充配對情境：一般 workflow（不在輸入點名 Flag）、branch／PR 審查、release 審查及純方法比較。先跑舊版配對基線、再跑新版；不變動既有 S1–S4，不將舊版無 RuleFile 視為領域答案失敗。

不變項：兩份 RuleFile、十一條 Rule、單一 Phase／九步驟；原有正確判準、來源區分、規則強度、案例與 frontmatter；不新增 Flag 清理期限、Git 分支政策、發布例外或確認閘門。不以全面載入案例彌補規則漏載。
