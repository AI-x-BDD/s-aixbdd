### 規劃順序

1. 從當時最新的 `main` 開一個短期 branch；branch 名稱依團隊既有命名規則，題目未提供，不能虛構。
2. 在同一個小批次完成日期格式修正與回歸測試。
3. 依專案既有 CI 執行 build、lint、unit test 及必要 integration test；具體指令與現況未提供。
4. 開 PR 並進行預估 30 分鐘的 review。
5. merge 前以團隊指定的 merge 方式把最新 `main` merge 到 branch；處理衝突後重新執行必要檢查，確認 CI 綠燈。
6. 以 merge commit 合併回 `main`；merge 後刪除短期 branch。
7. 若 `main` 的 CI 變紅，先修復或立即 revert `main`，暫停後續新變更整合。
