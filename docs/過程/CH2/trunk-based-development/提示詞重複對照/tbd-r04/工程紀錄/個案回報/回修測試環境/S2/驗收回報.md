## Phase 1：任務與判準

任務類型是需求規劃與變更切分，並涉及「功能尚未到曝光日」的整合技巧分析。沒有既有 branch、PR 或團隊 workflow 可供審查，因此不套用 workflow 審查規則；需求已足以直接形成整合計畫，不需案例參考。

本次判準如下：

- TBD 官方與 DORA 的 branch 壽命目標分開陳述：官方 short-lived branch 通常約 1～2 天；DORA 以不到一天為目標，兩者都不是把時間寫死的硬性門檻。
- 所有變更持續整合到單一 `main`，不建立四天的長期開發 branch；`main` 每次合併後仍須可工作。
- 未到週四的功能曝光使用 Feature Flag 隱藏；flag 關閉期間仍可逐支合併，曝光後安排移除 flag。
- 每個 PR 的變更需能獨立完成、驗證及合併；branch 壽命包含實作、30 分鐘 review 與 5 分鐘 CI。

## Phase 2：變更切分與整合計畫

### 變更切分

1. **PR 1：推薦清單 API 合約與後端支援** — 使用技巧：Feature Flag。API 以向後相容方式加入，推薦清單功能旗標先關閉。
2. **PR 2：推薦清單 UI** — 使用技巧：Feature Flag。UI 接上已合併的 API，但在同一旗標關閉時不顯示，既有畫面路徑維持原狀。
3. **PR 3：推薦清單追蹤事件** — 使用技巧：Feature Flag。追蹤只在旗標開啟時送出，關閉時不改變既有行為。

前三支 PR 各自完成後立即回到 `main`。四天內不保留一支包住全部工作的 branch；三支變更合併後，旗標維持關閉至週四。週四確認 `main` 綠燈後才開啟旗標，這是 release 動作，不把曝光提前到實作合併時。

### 技巧分析

- **Feature Flag：適用。** 功能必須週四才曝光，因此 API、UI、追蹤可以每天合併，直到週四才開啟；曝光後清理旗標。
- **Branch by Abstraction：不適用。** 輸入沒有大型重構或新舊實作逐步切換的需求。
- **新舊並存：不適用。** 輸入沒有既有 API 破壞性遷移；API 以向後相容方式新增即可。
- **Release Branch：不適用。** 輸入沒有已發布版本維護或 hotfix；工作持續在 `main` 上整合。

### 整合計畫

每支 PR 從最新 `main` 開短期 branch，完成後依序執行 build → lint → unit test → 必要的 integration test。CI 需在 5 分鐘內回饋，review 預留 30 分鐘；合併前更新到最新 `main`，合併後刪除 branch。若任一變更無法在當日完成，就再切成更小的可獨立變更。

## Phase 3：交付答覆

PR 1：推薦清單 API 合約與後端支援  — 使用技巧：Feature Flag

PR 2：推薦清單 UI  — 使用技巧：Feature Flag

PR 3：推薦清單追蹤事件  — 使用技巧：Feature Flag

每個 PR merge 後 `main` 為什麼仍可工作：API 是向後相容新增且旗標關閉；UI 在旗標關閉時不顯示；追蹤在旗標關閉時不送事件。既有使用者流程不依賴尚未曝光的推薦清單。

預估 branch 壽命（含等 review）：每支以當日完成並合併為目標；已知 review 30 分鐘加 CI 5 分鐘，共 35 分鐘，實際壽命為該小變更實作時間再加 35 分鐘。若實作加 35 分鐘超過一天，繼續拆小，不讓 branch 存活四天。

週四曝光：三支 PR 均合併且 CI 綠燈後，才開啟 Feature Flag；曝光後移除旗標與不再需要的隱藏程式碼。

## 交付前六題檢查

1. **能不能切到一天內可以 merge？** 可以。API、UI、追蹤已各自成為獨立 PR；若其中任一小變更仍超過一天，再向下切分。
2. **這個 PR 現在 merge，`main` 還能正常工作嗎？** 可以。每支 PR 都以旗標關閉及向後相容為前提。
3. **未完成功能能不能用 Feature Flag 隱藏？** 可以。三支 PR 共用同一旗標，週四前保持關閉。
4. **大改造能不能用 abstraction 讓新舊實作共存？** 本次沒有大改造，Branch by Abstraction 不適用。
5. **CI 能不能快速告訴我這次改動有沒有破壞系統？** 可以。依 build、lint、unit test、必要 integration test 執行，CI 目標回饋時間為 5 分鐘。
6. **這個 branch 明天還會存在嗎？** 目標是不會；每支 branch 在當日完成實作、review 及 CI 後合併。若會跨日，表示切分仍過大，需再拆分。
