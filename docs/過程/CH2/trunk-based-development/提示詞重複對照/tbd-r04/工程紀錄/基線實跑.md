## B：workflow 審查及比較

輸入：「團隊都從 main 開分支，寫碼半天、等 review 三天，CI 45 分鐘，紅燈晚上再看，發布前 freeze；規定 squash、兩位 reviewer。所以算 TBD 嗎？和 GitFlow 差在哪？branch 超過兩天是否一律違規？」

代理最終輸出：

- 目前不符合 TBD；從 main 開 branch 不能抵銷其他問題。
- branch 至少三天半，包含 review 等待；若 CI 另等，再加 45 分鐘。
- 官方 short-lived branch 通常約 1～2 天，DORA 目標少於一天；兩天不是硬性規則。
- CI 45 分鐘不符快速回饋目標；main 紅燈應立即修或 revert，不能晚上才處理。
- 發布前 code freeze 是常見錯誤，不能掩蓋整合延遲。
- squash 與兩位 reviewer 是團隊決策，可以與 TBD 並存，需避免造成等待。
- GitFlow 類是先隔離、完整後整合；TBD 是切小、持續整合、main 隨時可工作及發布。
- 超過兩天不是一律違規，是應檢查拆分或 review 的強烈警訊。本案有三天 review、CI 慢、紅燈延後及 freeze，整體不符合 TBD。

確認閘門：沒有互動批准閘門。送出前檢查：不能一天內 merge、紅燈延後不保證 main 可工作、未提供 flag 資料、未提供大型改造且 abstraction 不適用、CI 不夠快、branch 明天仍存在。
