## 完整最終回答

不一定。TBD 的核心判準是：

- 圍繞單一 trunk（通常是 `main`），不要維持長期開發分支。
- 頻繁整合回 `main`；DORA 建議至少每天一次，一天多次更好。
- `main` 隨時保持可工作；CI 失敗時先立即修復或 revert，再繼續其他開發。

因此，TBD 沒有要求一定要 rebase、一定使用 GitHub，也沒有規定 reviewer 一定要兩人。`squash`、merge commit、rebase merge、同步 `main` 時採 merge 或 rebase、branch 命名、reviewer 人數、GitHub 或 GitLab，以及是否禁止 direct push，都可以由團隊決定；只要不違反上述核心判準即可。

另外，branch 短命是強烈建議，不是固定硬性天數：TBD 官方通常以 1～2 天為短期 branch，DORA 以不到一天為目標，而且等待 review 的時間也要算進 branch 壽命。少量 active branches、merge 後刪除 branch、避免依賴 code freeze，也屬於強烈建議。
