# 前後比較

## 問題與證據

原 Skill 將方法判斷、策略與工作順序混在主檔，沒有 SOP、條件 READ、具名清單及使用／CHECK 的明確鏈。基線 audit SOP001，結構 S6 不符合本次模組化要求。原有用途與規則可由目標檔、案例及原始來源核對；六題有效基線均通過，未發現可證實的行為故障。

## 根因與範圍

根因是 Skill 主檔的結構安排；不是已證實的 TBD 判斷錯誤。根因確認後依核准藍圖搬移既有規則，保留用途、正確規則及來源強度。第一版藍圖漏了 workflow 對 Flag 清理等跨檔依賴，遭總指揮退回；修訂第二版後再取得確認。兩版與修正紀錄均保留，不把藍圖缺口冒稱為基線行為故障。

## 結構差異

| 項目 | 修改前 | 修改後 |
| ---- | ------ | ------ |
| 主檔 | 說明、方法、策略與流程混合；114 行 | 1 個 Phase、9 步 SOP；28 行 |
| 判斷規則 | 內嵌主檔 | 主幹整合 3 Rule＋變更拆分 5 Rule，共兩個主題 |
| 範例 | 既有案例檔 | 案例原文不變；每條 Rule 加同情境正反例 |
| 載入／使用／檢查 | 沒有明確具名清單鏈 | 條件 READ→具名清單→分析→草稿→逐條 CHECK／返回→交付 |
| workflow 審查 | 內嵌六項 | 必讀兩檔，含 Flag 清理；不靠技巧關鍵字觸發 |
| frontmatter 與案例 | 既有版本 | 逐字不變 |
| audit | SOP001 | 兩側各 0 error、0 warning |

C1–C24 的唯一位置與逐用途依賴見結構驗收.md。沒有新增領域政策，沒有為湊檔案數拆出 script 或 template。總字數因正反例及明確流程而增加，主檔變短不能證明 token、延遲或準確率改善。

## 驗收結論與限制

W1–W4 全部完成；六個乾淨對話行為情境及 S6 結構驗收全部通過；同步與檔案範圍核對通過。成果是結構改善，沒有已證實的行為改善。

前後模型／reasoning 未覆寫且繼承同父設定；實際 model ID、temperature、seed、服務快照未暴露，不能保證完全固定。主代理人工評分，非盲評。案例只測規劃／審查，未執行真實 Git、CI 或部署；純比較例外僅靜態核對。載入與 CHECK 的證據為明文鏈、輸出及讀取自述，隱藏思考不可獨立觀測。暫存環境路徑及所有證據已記錄。以上限制保持揭露，不降低原驗收判準。

個案驗收條件無須再調整；若將來要求統計可靠性或真實 Git 執行效果，需另訂可觀測實驗，不以本次樣本替代。
