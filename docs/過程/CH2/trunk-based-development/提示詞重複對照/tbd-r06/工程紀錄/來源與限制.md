## 原始來源核對（2026-10-17）

- [Short-Lived Feature Branches](https://trunkbaseddevelopment.com/short-lived-feature-branches/)：短命分支、先同步 trunk、Story 可拆多個 PR，且存在直接在 trunk 工作的替代方式。
- [DORA](https://dora.dev/capabilities/trunk-based-development/)：小批次每天整合、快速 CI、紅燈立即修復或 revert、導入能力前提。不同來源的 release 修補描述有差異，本次保留目標 Skill 明確採用的官方 trunk-first 政策，不宣稱所有來源一致。
- [Branch for Release](https://trunkbaseddevelopment.com/branch-for-release/)：晚切 release 分支、trunk-first 修正後移植，非新功能開發分支。
- [Branch by Abstraction](https://trunkbaseddevelopment.com/branch-by-abstraction/)：以抽象層支援分步遷移。
- [Feature Flags](https://trunkbaseddevelopment.com/feature-flags/)：隱藏未完成功能與清理 flag。
- [You're Doing It Wrong](https://trunkbaseddevelopment.com/youre-doing-it-wrong/)：避免長期共享開發分支與整合凍結。

## 隔離與限制

每題用獨立暫存目錄中的技能副本，乾淨子代理 fork_turns=none，只提供技能路徑、固定輸入位置與固定執行指令；不提供判準或工程分析。不同題之間也不共享對話。無模型覆寫，繼承同一父代理模型與 reasoning 設定；底層 model ID、temperature、seed 與服務快照不可查，因此只能保證工具層相同設定，不能宣稱隨機性受控。修改後必須建立新的乾淨子代理，不能沿用已實測對話。

測試環境沒有真實應用程式、Git remote 或 CI，驗證的是規劃與審查產出，不能證明 Git 寫入、部署或真正 main 的可工作性。未做操作授權行為的普遍性推斷。資源讀取清單為子代理自述，需與當次工具呼叫紀錄交叉查核；原始回答完整保存。副本檔案雜湊留存，S2 輸入因環境修正而改變已明示，技能副本未改動。
