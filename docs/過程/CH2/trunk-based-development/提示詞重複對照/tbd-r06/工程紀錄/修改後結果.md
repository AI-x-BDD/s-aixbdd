六題皆自述讀取主幹整合與變更拆分 RuleFile；S1–S4 另讀案例，S5、S7 不讀案例仍保留適用判準。S5 兼有比較但沒有誤走純比較例外。S7 以未提示技巧名稱的輸入取得 Flag 清理，與 S6 的一般 workflow 必讀路徑一致。

「分析前載入、清單使用與 CHECK」的可核對證據包含主檔 READ→具名清單→THINK→CHECK 的明文鏈、完整回答中的適用規則及資源讀取自述。無法從最終回答獨立觀察代理的隱藏思考、內部清單或 CHECK 執行情形，不將自述當作完整工具事件追蹤；本項限制不改寫固定判準。

## 環境、隔離與副作用

前後分別使用每題獨立暫存目錄與全新 fork_turns=none 子代理，未提供工程上下文、判準或預期答案；相同測試指令、輸入與判準，只替換受測 Skill 版本及必須不同的副本路徑。無需預先回覆，因目標 Skill 沒有確認閘門。後測以獨立情境並行排程，代理任務為 after_s1、after_s2、after_s3、after_s4、after_s5、after_s7；基線沿用已封存紀錄。平台未顯示可另行保存的 agent UUID。

前後環境位置、逐題完整輸入、初始雜湊與模型設定分別見「全部實跑環境基準.json」「修改後環境.json」。前後輸入逐字相同，判準相同；六題環境的檔案雜湊均未改變，無新增檔案。詳細逐題結果見「前後副作用與同題檢查.json」。不執行真實 Git 寫入、應用程式測試或部署；此處只驗證規劃／審查回答。

模型與 reasoning 均繼承同一父代理設定，無覆寫；底層 model ID、temperature、seed、服務快照未暴露，不能保證完全相同，也不填造數值。人工評分非盲評；每題各一次有效前測及後測，不據此宣稱統計穩定性。S2 初次測試設計不一致及修正輸入重跑另保留，後測未改判準；S7 在施工前先完成基線。
