  1. PR 1：修正 main
      • 從 main 開短期修補分支，加入 bug 修正與回歸測試。
      • 同步最新 main，通過 CI、review 後合併，再刪除修補分支。

  2. PR 2：回補 v2.4
      • 使用既有 release/2.4；若不存在，從 production 實際部署的 v2.4 tag／commit 建立，不能從目前 main 切。
      • 開短期回補分支，僅 cherry-pick 已驗證的修正；若版本差異造成衝突，調整並重新驗證 v2.4 的回歸測試。
      • 通過該版本 CI、review 後合併至 release/2.4，刪除回補分支。此 PR 不改 main。

  3. 發布與分支收尾
      • 從 release/2.4 建置、驗證並標記 v2.4.1，再部署、確認 bug 已修復。

      • v2.4 停止維護後，刪除 release branch，保留發布 tag。
