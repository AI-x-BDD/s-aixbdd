## 後續固定做法

1. 用短版提示詞呼叫 Skill Engineering。
2. 驗收分三項核對：原規則是否完整保留、適用規則是否載入、答案是否完整使用。
3. 失敗先定位：有文字缺口就回修並重測；要求已明確存在卻沒遵守，記為執行失敗，不自動新增重複規則。未全過的候選不當成已驗收成果套用。

不用每個 Skill 再跑長短各一次；固定沿用這個驗收方式。

## 實驗界線

- 工程與共同測試使用 Herdr 取得的全新 Codex session；介面顯示 GPT-6.1-Sol medium fast。保留了 slash command 不支援時的一致介面適配，不當成提示詞推理結果。
- 根因及藍圖都經總指揮介入，兩版共用已確認的模組化方向與執行環境指示。因此這是完整工作流程比較，不是兩段文字單次無人審查生成的盲測。
- 原第一項在固定版本、不同題目組織／上下文下結果不同，但未單獨隔離各因素；原第二項在固定候選控制組未再重現，能確認的是原執行漏載，不能寫成已證明純採樣隨機性。
- r03 回修正反例用了已知失敗題，後測是回歸，不能冒充未見過的測試。f03b 另有全域 MEMORY.md 搜尋，列為隔離限制；首次 c03b 無此紀錄且已通過，r03 本地亦另有 hotfix 回歸。
