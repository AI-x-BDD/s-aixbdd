# trunk-based-development 最佳化前後比較

本輪以同一原版執行長、短提示詞兩次重構，成果各自保存，正式 Skill 待選版後套用。

## 比較與證據入口

- [長短提示詞比較](長短提示詞比較.md)：兩次設計、驗收、審核介入與限制。
- [長版前後比較](長提示詞/前後比較.md)、[短版前後比較](短提示詞/前後比較.md)。
- [原版原始輸出](原版原始輸出.md)、[原版評分](原版評分.md)。
- [共同測試輸入與判準](測試輸入.md)、[原有規則追溯](原有規則逐項追溯.md)。
- [流程確認紀錄](流程確認紀錄.md)、[隔離與共同操作條件](代理輸入與隔離.md)。
- 原版快照：`最佳化前技能/`；兩個最終快照分別位於各版 `最佳化後技能/`。

## 與 conventional-commits 相同的紀錄範圍

保留原版與重構版 package、根因與工程藍圖、施工及 primitives 紀錄、結構診斷與同步結果、相同輸入的實際前後回答、逐題評分、完整檔案差異、驗收前後雜湊與驗證限制。本輪另外保存兩份提示詞原文、初版與修訂設計、主代理審核回饋，以及長短版橫向比較。

conventional-commits 前次包含已確認行為修正；本輪目的是保持原有行為並重構，不能套用前次發現的錯誤或宣稱同樣提升準確率。所有行為驗收都是文字情境，沒有實作產品、真的執行 CI 或發布。

## 目前狀態

兩版已完成從根因、藍圖、施工、同步到實際驗收及證據保存的流程；共同十題三版均10/10。長版自備三題固定10項通過，短版自備五題為3題通過、2題部分通過，缺項保留，不能稱全部驗收條件都通過。暫時worktree已移除。未commit、未push，正式Skill未套用任何實驗版。

最終檔案保存與未採用核對見 [保存核對](最終保存核對.json)；錄影可使用 [追問釐清與影片素材](追問釐清與影片素材.md)。
