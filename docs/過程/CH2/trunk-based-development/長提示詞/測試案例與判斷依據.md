# trunk-based-development 規則模組化：隔離驗收案例

- 受測 Skill：`.agents/skills/trunk-based-development/`（同步副本為 `.claude/skills/trunk-based-development/`）
- 執行方式：由外層安排乾淨對話／隔離環境，以相同模型、設定、輸入與判準分別替換修改前後的受測 Skill 版本。
- 本檔用途：固定輸入與可觀察判準；原始輸出與逐案結果由執行代理另存於本紀錄目錄。
- 限制：本檔尚未包含外層執行的模型輸出；靜態分析不能代替行為驗證。

## 共通執行提示

```text
請使用指定的 trunk-based-development Skill 回答下列情境。只處理情境中的需求，保留 Skill 原本的輸出格式與來源區分。請列出拆分結果、使用的技巧、每個變更合併後 main 仍可工作的理由，以及 branch 壽命；若是 workflow 審查，請指出違反的 TBD 核心規則與修正順序。不要執行 Git 寫入、commit、push 或修改檔案。
```

## 案例 S1：尚未完成、但需要每日整合的功能

### 輸入

```text
產品要新增「帳單匯出」功能，包含 API、下載頁面、權限檢查、操作追蹤與測試，預估四個工作天；產品要求週五才對使用者開放。請規劃如何拆成可獨立整合的 PR，判斷是否需要特殊技巧，並依 Skill 的固定格式說明每個 PR merge 後 main 為什麼仍可工作、branch 預估活多久。
```

### 判斷依據

- 應把需求切成多個可獨立整合的小變更，而不是建立一個涵蓋四天工作的長期 feature branch。
- 因為功能週五前不能曝光，應建議 Feature Flag，且指出 Deploy 與 Release 的差別或等價的關閉方式。
- 每個 PR 都應說明 main 仍可工作的理由，branch 壽命應以短期（通常當天或很短）描述；不得把四天當成單一 branch 壽命。
- 不要求固定的 branch 命名、merge/rebase 或 reviewer 人數；這些屬團隊規則，除非輸出明確標為團隊自行決定。

## 案例 S2：跨多日的客戶端重構

### 輸入

```text
現有產品所有呼叫都直接依賴舊的 REST client，團隊想在一週內換成新的 GraphQL client，但不能讓 main 進入「部分呼叫已換、部分呼叫已壞」的狀態。請用 trunk-based-development 規劃每日可 merge 的步驟，指出應使用的技巧，以及每一步的可工作理由。
```

### 判斷依據

- 應選 Branch by Abstraction 或等價的新舊並存策略，不應建議一條活一週的 `refactor/*` 分支最後一次合併。
- 步驟應包含先建立 abstraction、讓舊 REST client 接上、加入 GraphQL implementation、逐步切換呼叫者、最後移除舊實作；順序可用同義名稱但語意須完整。
- 每一步都應保持 main 可工作並能每日整合；不得把尚未完成當成可接受的 main 破壞。

## 案例 S3：長分支、紅色 CI 與已發布版本修補

### 輸入

```text
團隊有長期存在的 develop 分支；某個 feature branch 已活 9 天，CI 目前失敗。生產環境仍在 2026.10，main 已開始 2026.11 的開發；現在發現一個只影響 2026.10 的 bug。請審查這個 workflow 是否符合 TBD，列出應先處理的問題與修正順序，並說明 bug 應在哪裡修以及如何帶回發布分支。
```

### 判斷依據

- 應指出長期共同開發分支、9 天 feature branch 與紅色 CI 都違反或阻礙 TBD；main 紅時先修復或立即 revert，不應繼續堆新功能。
- 已發布版本的 bug 應先在 main 修復並驗證，再 cherry-pick 到 `release/2026.10`；release branch 只承載該版本穩定、修 bug 與發布，不承載 2026.11 新功能。
- 應區分 TBD 核心規則、強烈建議與團隊自行決定，不得把 branch 命名、merge/rebase 或 review 方式說成 TBD 硬性要求。

## 保存要求

外層執行代理應為修改前與修改後各建立獨立結果檔，至少保存：

1. 完整輸入（共通執行提示與該案例輸入）。
2. 完整原始輸出，不以摘要取代。
3. 使用的模型、設定、隔離方式、受測 Skill package 路徑與版本雜湊。
4. 依本檔判斷依據逐項標記通過、未通過或無法判斷，並記錄測試限制。
