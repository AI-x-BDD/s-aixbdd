# 長短提示詞重構比較

兩版的 TBD 主要策略與共同十題結果接近；初版設計、最終分檔方式與自備驗證的完整度有明顯差別。這是同一操作條件下各一次工程流程的觀察，不能推論長提示詞必然較好。

## 怎麼比較

兩次均從 `e588ae1d1fc87b3456a56af08e1379f131333050` 建立 detached worktree，以不繼承主分析對話的新代理執行。保留各自原始提示詞，模型／reasoning 沒有覆寫；精確服務端版本與隨機性參數未知。

共同十題在施工前固定，施工代理未取得測試及判準；原版與兩版分別使用新驗收代理，只給輸入、不給判準。每版十題依序共用上下文，不是每題獨立。主代理事後依同一判準核對，另以原版24組契約逐項檢查，避免只看情境答對。

兩個施工代理還受到相同操作封套、repo指引及skill-engineering約束；封套本身比短提示詞長。因此比較單位是兩份提示詞在這套流程下的成果，不是完全無背景的裸提示詞長度實驗。隔離是指令及worktree隔離，不是檔案權限封鎖；版本名稱也可見，非雙盲。

詳見 [執行安排](執行安排.md)、[代理輸入與隔離](代理輸入與隔離.md)、[提示詞基準](提示詞基準.json)。

## 審核介入也是結果的一部分

兩版藍圖都經兩次退回，第三版才通過；短版第三版另補實際檔案路徑與觸發條件。主代理依既有skill-engineering規範審核，未向任一版提供另一版設計，也未指定檔數；仍可能因共同審核而使最終成果趨近，不能把最終差異全部歸因於原始提示詞。

長版首次驗收共同十題和自備三題都符合各自固定判準，逐條原文核對卻發現C10決策順序、C22六項交付檢查漏掉。補回後又發現六項檢查落在Bad Example小節，要求只移位置；兩個尚未完成的驗收代理因此中止，不評分，凍結後再用新代理重跑。首次package與已完成raw另存於 [首次驗收版本](長提示詞/首次驗收版本/共同案例評分.md)，未覆寫或當作最終驗收。

這些是同一次工程流程的審核返工，不是重新給提示詞抽樣到通過。期間沒有遇到必須變更共同規則或環境才可繼續的執行歧義，所以沒有改標試跑、重建正式比較；若只因審核返工重置，反而會隱藏成本。完整介入見 [流程確認紀錄](流程確認紀錄.md)。

## 實際行為與證據完整度

原版、長版最終、短版共同十題均為10/10；這組固定判準未呈現明顯行為差距。長版首次版也曾10/10卻漏契約，故不能將分數當作完整等價證明。

長版自行準備三題，修改前與修改後以相同輸入、判準及乾淨代理實跑，固定判準共10項；最終三題仍為4/4、3/3、3/3，合計10/10項。修改前第三題另有把官方1–2天說成「上限」的措辭張力，沒有事後改寫基準或變更判準。

短版自行準備修改後回歸，S2–S5最初即有，S6在第三版施工前新增；沒有自備同題修改前實跑。S1是靜態檢查，不算行為題。外層另外補上的原版／兩版共同十題，不能算作短提示詞主動產出的修改前證據。

短版自備S4漏旗標清理、S5漏含review分支壽命等規劃欄位，保留缺項，不重試取代。沒有對這五題執行原版同題，故不能判定這些缺項是重構造成的退步。共同十題的S2另加入未提供的「週五」措辭；S6的release branch壽命建議要保留團隊政策條件，不能擴大成原規則。詳見各版實際raw及評分。

## 完整流程帶來的判斷

- **初版設計：有明顯不同。** 長版已主動規劃規則檔；短版最初只補SOP。共同流程審核使兩者最後都完成分檔。
- **最終結構：有局部差異。** 都是SOP、按需RuleFile、正反例、具名結果與CHECK；五檔十五Rule與八檔九Rule代表不同主題邊界，不能用多寡評優。
- **共同實測：大同小異。** 三版共同十題均10/10，仍保留判準外措辭差異與未測範圍；不把靜態audit通過說成行為改善。
- **證據完整度：有明顯不同。** 長版主動做自備同題前後測；短版沒有。但長版仍曾漏原規則，提示詞詳盡也不能取代逐條保持核對。

正式Skill尚未套用任何候選；兩個成果均可由保存的完整package與diff重建。提交訊息只有 [草稿](提交訊息草稿.md)，沒有commit或push。
