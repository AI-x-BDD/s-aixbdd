# 追問釐清與影片素材

## 這次是在比什麼

同一份 trunk-based-development、同一個基準，讓兩個乾淨代理分別收到長短提示詞，依同一套 skill-engineering 完成重構。主代理依授權處理根因與藍圖確認，不需要每個內部閘門再找使用者。兩版的初稿、退回理由與修改都保存，不能只展示最後結果。

## 原版真的有行為錯誤嗎

原版共同十題10/10。已確認的是缺正式SOP與規則載體等結構問題，不能把audit的SOP001當成TBD建議錯誤。長版自備修改前輸出另有把1–2天說成上限的措辭張力，單次觀察不足以宣稱穩定錯誤或修復。

## 只用短提示詞能完成嗎

在本次既有repo指引、skill-engineering與共同操作封套下，短版能走到施工、同步、驗收及成果保存。初版只補SOP，經審核才補模組化；自備回歸三題通過、兩題部分通過，不能說完全自動且一次全通過。這也不是只給裸短句、完全沒有其他上下文的試驗。

## 長提示詞有沒有保證結果更好

沒有。長版主動準備自備同題前後實測，但首次共同十題全過仍漏了兩組原有契約，靠逐條核對才發現。它的證據比較完整，不代表不會漏規則。兩版主要TBD策略接近，分檔方式與自備證據則不同。
