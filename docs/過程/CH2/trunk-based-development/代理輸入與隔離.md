# 代理輸入與隔離

## 施工代理

- 長版：`/root/tbd_long`，`worker`，`fork_turns=none`。
- 短版：`/root/tbd_short`，`worker`，`fork_turns=none`。
- 兩者均未指定 model 或 reasoning override，沿用本次工具的預設設定。精確服務端模型版本與隨機參數未知。
- 各代理只收到自己 worktree 的路徑、自己的原提示詞檔案路徑、紀錄目錄與下列共同操作安排；沒有收到本次主對話、另一版提示詞／結果或共同評分判準。各版名稱對代理可見，因此不是雙盲實驗。
- repository 基準中本來就含兩份提示詞所在的歷史提案；已明確要求代理不讀比較文件／另一版提示詞。這是指令隔離，不是作業系統層級的檔案存取隔離。

共同操作安排（兩邊僅替換 worktree、提示詞檔與版本目錄名稱）：

```text
你負責獨立重構實驗的一次執行。你不是唯一在工作的人；其他代理有各自目錄，勿撤銷他人修改，勿讀其他實驗的提示詞、分析或成果。
所有 shell workdir 必須明確指定自己的 worktree。
只修改該 worktree 的 .agents/skills/trunk-based-development/、同步的 .claude/skills/trunk-based-development/，以及該版本的紀錄目錄；不要寫主工作目錄。
先讀該 worktree AGENTS.md，再讀你的完整任務提示詞，依原文執行，載入 skill-engineering 與需要的 primitives、writing-for-agents。
保持既有用途及行為，若發現行為錯誤另記不修；紀錄位置覆寫為上述版本目錄、中文 Markdown 檔名；不 commit/push、不改主工作目錄。
根因與藍圖各完成時，寫入檔案並 send_message /root 請審查，等待主代理明確確認後才進下一階段；使用者已授權主代理審核這些閘門。
遇到執行不明確先傳具體阻礙，勿猜測通過或假裝完成。
共同基準行為測試由外層執行，不把它算作你自行產出的結果；你的提示詞若要求自行實測，仍需自行設計及實跑，原始輸出必須保存。
若需要乾淨驗收代理，可請 /root 安排（不要自己爭用併發名額）。
本次是各一次實驗，勿看比較文件，勿讀主工作目錄新增紀錄。
最後保存完整 package diff、自己實際執行的結構診斷與同步輸出、變更前後紀錄及限制。
先完成蒐證與根因報告並送主代理審核。
```

這份操作安排本身比原短提示詞更長；因此本實驗比較的是「相同操作封套與既有 repo／skill-engineering 下，兩份任務提示詞的結果」，不是只給裸短句與裸長句、完全無其他上下文的比較。共同封套會縮小兩者差異，結論須保留此限制。

## 共同行為驗收

原版、長版、短版各使用新代理，`fork_turns=none`；只提供受測 package 路徑、相同 S1–S10 輸入、只讀限制與輸出位置，依受測 Skill 按需載入資源。執行代理看不到固定評分判準，主代理事後核對。

同一版內十題依序共享代理上下文；不同版本彼此獨立。所有題目為假設文字情境，沒有真的執行產品 CI、部署或 Git 寫入。受測 package 前後做 SHA-256 核對。

## 施工自備案例

長版自行準備三個案例並要求修改前後乾淨實跑；外層只提供代理資源與保存輸出，不把外層共同十題說成長版自行準備的測試。短版依既有 skill-engineering 準備自己的修改後回歸情境，是否有修改前同題實跑依實際紀錄判定。
