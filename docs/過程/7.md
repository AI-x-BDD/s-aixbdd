## 1. `$double-diamond`：分析 Step 7

### 輸入

```text
$double-diamond
docs/需求清單.md:237-283
```

指定段落要求：

- 先檢查目前散落的 validation，不要直接大改。
- 先補測試描述複合錯誤，例如 `-1,,2`。
- 清楚劃分 validation 責任，必要時才抽出 parser、validator 或 input model。
- 保留前面各 Step 的測試，不為了架構漂亮而過度設計。

### Agent 讀取的證據

Agent 讀取需求、技能、現有實作與測試，也查閱先前練習的紀錄索引。當時的程式流程是：

1. `tokenize()` 切割輸入。
2. `add()` 先檢查結尾是否為空 token，若是就拋錯。
3. 迴圈使用 `Integer.parseInt()` 解析、收集負數並加總。
4. 迴圈結束後，才回報收集到的負數。

依程式流程推導，`-1,,2` 在解析空字串時就會中斷，已收集的負數不會回報。自訂 delimiter 標頭缺少換行時，也沒有先驗證就執行 `substring()`。此時尚未執行測試；後續紅燈才實際驗證這些問題。

### 判斷與不確定性

Agent 判斷：需求同時包含問題與候選解法。「錯誤處理不明確」是問題；抽出三種類別只是可選方案。

最大的未知是複合錯誤的回報契約，所在階段為 Define：

- 回報第一個錯誤、按優先順序回報，還是一次回報全部？
- 「格式不合法」涵蓋哪些情況？

需求提到多個問題可能同時存在，但沒有直接規定必須全部回報。

### Problem Statement

| 項目 | 定義 |
| --- | --- |
| 對象 | String Calculator 的呼叫端與維護者 |
| 問題 | 回報結果受檢查順序與底層解析例外影響，複合錯誤缺少明確契約 |
| 影響 | 呼叫端難以預期失敗結果；實際使用影響待驗證 |
| 成功指標 | 已知錯誤與複合錯誤有明確測試，前面 Step 的測試全部通過 |
| 限制 | 先補測試、不直接大改、不為架構而增加類別 |

### 候選方案

| 方案 | 做法 | 取捨 |
| --- | --- | --- |
| A：遇錯即停 | 依輸入順序回報第一個錯誤 | 最簡單，但一次只能修一項 |
| B：分階段驗證 | 先格式、再數值；格式通過後收集所有負數 | 責任清楚，但不同種類錯誤不一起回報 |
| C：收集可辨識錯誤 | token 可辨識時收集缺值、非法數字與負數；標頭無法解析時停止 | 回饋完整，但需定義順序、重複回報與訊息格式 |

Agent 建議採 C，先以私有方法分清解析、驗證與加總，不先建立獨立類別。最便宜的驗證是為 `-1,,2`、`-1,2,`、`1,x,-3` 與缺少換行的標頭列出預期結果，再寫測試。

這一步只有分析，沒有修改程式或執行測試。

## 2. 「依建議，do it」：實作方案 C

### 輸入

```text
依建議，do it
```

Agent 使用 TDD 技能，讀取 `AGENTS.md`、`pom.xml`、需求與現有程式，確認工作目錄當時沒有變更。實作沿用公開方法 `add(String)` 作為測試介面，沒有建立新分支。

### 回報契約

Agent 在實作前說明以下決定：

- 缺值或非法數字按 token 位置回報，位置從 1 起算。
- 所有負數依輸入順序收集，統一放在訊息最後。
- 不同錯誤以 `; ` 分隔。
- 最後一個空 token 若來自結尾 delimiter，只回報結尾 delimiter，不再重複回報缺少數字。
- 自訂 delimiter 標頭無法解析時直接停止。

這些是採用方案 C 後的具體實作決定，並非原始需求已逐項指定。

### 第一輪：缺少數字與多個負數

先新增 `missingNumberAndAllNegativesAreReportedTogether`，輸入 `-1,,-3`，要求同時回報缺少第二個數字與兩個負數。

執行 `mvn -q test` 得到紅燈：

```text
expected: <Missing number at position 2; Negative not allowed: -1,-3>
but was: <For input string: "">
Tests run: 18, Failures: 1, Errors: 0, Skipped: 0
```

這驗證了分析時指出的提前中斷問題。接著抽出私有方法 `parseAndValidate(String[] parts)`：

- 遇到空 token，先收集缺值錯誤，再繼續處理後面的 token。
- 用 `StringJoiner` 分別收集一般錯誤與負數。
- 驗證通過才回傳 `int[]`，由 `add()` 加總。

再次執行 `mvn -q test`，成功退出，18 個測試通過。這時結尾 delimiter 的檢查仍在 `add()`。

### 第二輪：結尾 delimiter 與負數

新增 `trailingDelimiterAndNegativesAreReportedTogether`，輸入 `-1,2,`。

紅燈結果：

```text
expected: <Input must not end with a delimiter; Negative not allowed: -1>
but was: <Input must not end with a delimiter>
Tests run: 19, Failures: 1, Errors: 0, Skipped: 0
```

原本在迴圈之前拋錯，因此負數沒有機會被收集。Agent 將結尾檢查移入 `parseAndValidate()` 的空 token 處理：最後一格且 token 數量大於 1 時，記錄結尾 delimiter 錯誤，其餘空格記錄缺值。

再次執行 `mvn -q test`，19 個測試通過，原有結尾錯誤訊息也保留。

### 第三輪：非法數字後仍收集負數

新增 `invalidNumberDoesNotHideLaterNegatives`，輸入 `1,x,-3`。

紅燈結果：

```text
expected: <Invalid number at position 2: x; Negative not allowed: -3>
but was: <For input string: "x">
Tests run: 20, Failures: 1, Errors: 0, Skipped: 0
```

Agent 在整數解析處捕捉 `NumberFormatException`，記錄 token 位置與內容後繼續處理。不能解析成 Java `int` 的內容，包括超出範圍的整數，都使用 `Invalid number` 訊息。

再次執行 `mvn -q test`，20 個測試通過。

### 第四輪：無法解析的自訂標頭

新增參數化測試 `malformedCustomDelimiterHeaderIsRejected`：

| 輸入 | 問題 |
| --- | --- |
| `//;` | 缺少換行 |
| `//;1;2` | 缺少換行 |
| `//` | 缺少 delimiter 與換行 |
| `//\n1,2` | delimiter 為空 |

統一預期：

```text
Invalid delimiter header: expected //delimiter followed by a newline
```

執行測試後，24 個案例中有 4 個失敗：前三個拋出 `StringIndexOutOfBoundsException`，第四個被繼續切割，回報了缺值與結尾 delimiter。

Agent 在 `tokenize()` 加入 `headerEnd <= 2` 檢查，確認換行存在且 delimiter 非空，否則直接拋出 `IllegalArgumentException`。

再次執行 `mvn -q test`，24 個測試通過。

### 補充驗證

接著增加 6 個案例，現有實作已能通過，沒有再修改實作或刻意製造紅燈：

| 輸入 | 驗證內容 |
| --- | --- |
| `-1,,2` | 需求原例：缺值與負數一起回報 |
| `//;\n-1;;2` | 自訂分隔符下的複合錯誤 |
| `//\|\n-1\|\|2` | 正規表示式特殊字元作為分隔符 |
| `-1\n\n2` | 換行分隔下的複合錯誤 |
| `//;\n` | 有標頭但沒有數字，回報 `Missing number at position 1` |
| `,x,-1,,2147483648,-1,` | 多種錯誤順序、整數範圍、重複負數與結尾錯誤不重複分類 |

最後一個案例的完整預期訊息：

```text
Missing number at position 1; Invalid number at position 2: x; Missing number at position 4; Invalid number at position 5: 2147483648; Input must not end with a delimiter; Negative not allowed: -1,-1
```

「不重複分類」是指結尾空 token 不同時回報結尾 delimiter 與缺值；輸入中出現兩次的負數仍保留兩次，不去除重複值。

### 完整驗證與修改範圍

執行 `mvn test`：

```text
Tests run: 30, Failures: 0, Errors: 0, Skipped: 0
BUILD SUCCESS
```

`git diff --check` 通過。Maven 顯示來自 Guice 的 `sun.misc.Unsafe` 棄用警告，沒有造成建置或測試失敗。

| 檔案 | 修改 |
| --- | --- |
| `src/main/java/calculator/StringCalculator.java` | 標頭驗證、錯誤收集、驗證後才加總 |
| `src/test/java/calculator/StringCalculatorTest.java` | 增加 13 個執行案例，保留原有 17 個案例 |

兩個檔案合計新增 96 行、刪除 8 行。沒有新增 parser、validator 或 input model 類別，也沒有提前實作 Step 8。

### 完成回覆

Agent 說明原本最大問題是解析、驗證與加總混在一起，格式錯誤會讓負數回報中斷。現在由 `tokenize()` 處理標頭，`parseAndValidate()` 收集內容錯誤，全部合法才加總。
