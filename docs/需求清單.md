# String Calculator 需求清單

# Step 1：基本加法

使用 Java 實作 String Calculator 的第一個需求。

目前只需要完成以下功能：

```text
add("")      -> 0
add("1")     -> 1
add("1,2")   -> 3
```

要求：

1. 建立 `StringCalculator` 類別。
2. 建立：

```java
int add(String numbers)
```

1. 使用測試先描述需求，再完成實作。
2. 目前只處理：
   - 空字串
   - 一個數字
   - 兩個以逗號 `,` 分隔的數字
3. 不要實作後面尚未要求的功能。
4. 完成後執行相關測試。
5. 告訴我：
   - 修改了哪些檔案
   - 實作了什麼
   - 測試結果

---

# Step 2：支援任意數量的數字

基於目前的 String Calculator 繼續開發。

新增需求：

```text
add("1,2,3")       -> 6
add("1,2,3,4,5")   -> 15
```

也就是：

```text
add()
```

現在必須能處理**任意數量**、以逗號 `,` 分隔的數字。

要求：

1. 保留 Step 1 的所有行為。
2. 先新增測試。
3. 再修改實作。
4. 不要限制只能處理固定數量的數字。
5. 不要提前實作下一個 Step 的換行、自訂分隔符或負數功能。
6. 執行全部相關測試。
7. 確認舊測試沒有被破壞。

完成後告訴我：

- 新增或修改了什麼
- 為什麼這樣實作
- 測試結果

# Step 3：支援換行分隔符

基於目前實作新增以下需求。

除了逗號 `,` 之外，現在也允許使用換行：

```text
\n
```

例如：

```text
add("1\n2,3") -> 6
add("1\n2\n3") -> 6
```

要求：

1. `,` 與 `\n` 都可以作為分隔符。
2. 同一個輸入可以混合使用。
3. Step 1、Step 2 的功能必須繼續正常。
4. 先加入測試，再實作。
5. 不要提前支援自訂分隔符。
6. 不要一次重寫整個程式，除非現有設計真的阻礙這個需求。
7. 執行完整測試。

完成後告訴我：

- 加了哪些測試
- 核心修改在哪裡
- 全部測試是否通過

# Step 4：處理不合法的結尾分隔符

新增輸入驗證。

以下輸入不應該被當成合法輸入：

```text
add("1,2,")
add("1\n2\n")
```

當輸入最後是一個分隔符時，必須回報錯誤。

要求：

1. 為這個錯誤情境新增測試。
2. 保留所有目前已完成的合法輸入。
3. 使用清楚的 Exception。
4. 測試必須驗證錯誤真的發生。
5. 不要順便加入其他尚未要求的 validation。
6. 執行全部測試，確保沒有 regression。

Regression 的意思是：

```text
新增功能之後，原本正常的功能被弄壞。
```

完成後告訴我：

- 哪種輸入會失敗
- 使用什麼 Exception
- 測試結果

# Step 5：支援自訂分隔符

新增自訂 delimiter 功能。

Delimiter 就是「分隔數字的符號」。

輸入格式：

```text
//[delimiter]\n[numbers]
```

例如：

```text
add("//;\n1;2") -> 3
add("//|\n1|2|3") -> 6
```

要求：

1. 解析輸入開頭的：

```text
//
```

1. 找出 `\n` 前面的自訂分隔符。
2. 使用這個分隔符解析後面的數字。
3. 原本的逗號與換行功能仍然必須正常。
4. 先寫測試，再改實作。
5. 如果目前 parsing 邏輯開始混亂，可以做小幅重構。
6. 不要提前處理負數。
7. 執行全部測試。

完成後告訴我：

- 如何找出 delimiter
- 如何解析 numbers
- 是否有重構
- 測試結果

# Step 6：禁止負數

新增負數驗證。

例如：

```text
add("-1,2")
```

必須丟出 Exception。

錯誤訊息格式：

```text
Negative not allowed: -1
```

如果存在多個負數：

```text
add("-1,2,-3")
```

錯誤訊息必須包含所有負數：

```text
Negative not allowed: -1,-3
```

要求：

1. 先加入單一負數測試。
2. 再加入多個負數測試。
3. 找出所有負數之後，再一次回報。
4. 不要只回報第一個負數。
5. 原本所有正常輸入繼續正常。
6. 執行完整測試。

完成後告訴我：

- 負數在哪個階段被檢查
- 多個負數如何收集
- 測試結果

# Step 7：處理多種輸入錯誤

現在開始整理 validation。

Validation 就是：

```text
檢查輸入是否合法。
```

請讓 String Calculator 能明確處理目前已知的錯誤，例如：

```text
負數
結尾有 delimiter
缺少數字
格式不合法
```

例如：

```text
-1,,2
```

這種輸入可能同時存在不只一個問題。

要求：

1. 先檢查目前程式有哪些 validation 已經散落在不同地方。
2. 不要直接大改。
3. 先補測試描述複合錯誤情境。
4. 讓 validation 有清楚的責任。
5. 如果合理，可以抽出：
   - parser
   - validator
   - input model
6. 但不要為了「架構漂亮」過度設計。
7. 所有前面 Step 的測試都必須通過。

完成後告訴我：

- 原本最大的設計問題是什麼
- 是否做了重構
- validation 現在放在哪裡
- 測試結果

# Step 8：加入 multiply 並共用解析邏輯

最後新增：

```java
int multiply(String numbers)
```

例如：

```text
multiply("")        -> 0
multiply("2")       -> 2
multiply("2,3")     -> 6
multiply("2,3,4")   -> 24
multiply("2\n3")    -> 6
multiply("//;\n2;3") -> 6
```

`multiply()` 必須沿用目前 `add()` 已經支援的：

```text
數字解析
delimiter
自訂 delimiter
validation
負數檢查
```

要求：

1. 不要複製一套 `add()` 的 parsing 程式。
2. 找出 `add()` 與 `multiply()` 真正共用的邏輯。
3. 將「解析輸入」與「進行運算」分開。
4. 先加入 multiply 測試。
5. 再進行必要重構。
6. `add()` 的舊測試必須全部保持通過。
7. `multiply()` 的新測試也必須通過。
8. 不要為未來不存在的需求建立複雜 abstraction。

最後請整理：

- 最終類別結構
- 每個類別的責任
- `add()` 與 `multiply()` 共用了哪些邏輯
- 是否有 duplicated code
- 所有測試結果
