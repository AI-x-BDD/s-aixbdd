# Rule 1 - 委派必須完整對應已確認的腳本設計

- 委派 `skill-form-script` 時，必須指定已確認的腳本路徑、輸入、輸出、命令列參數、依賴、Python 版本要求與副作用。
- 委派內容不得加入、刪除或改寫未經確認的腳本職責。

## Good Example

- 委派內容完整交付已確認的索引腳本介面。

情境：

1. 已確認的設計是 `scripts/build_index.py` 讀取 `--input`，寫入 `--output`，不使用網路。
2. 委派 `skill-form-script` 時，逐項指定上述路徑、參數與副作用，並指定已確認的 Python 版本和依賴。

## Bad Example

- 同一個設計被委派為額外下載資料的腳本。

情境：

1. 已確認的設計是 `scripts/build_index.py` 讀取 `--input`，寫入 `--output`，不使用網路。
2. 委派 `skill-form-script` 時，要求腳本另外從網路下載資料，並自行決定 Python 版本和依賴。

# Rule 2 - SOP 委派步驟必須指出可執行的命令

- 目標 SOP 的 `DELEGATE` 步驟必須使用 `uv run --script` 執行已確認的 `.py` 檔案，並列出指定步驟所需的輸入與輸出參數。
- 腳本路徑必須相對於目標 Skill 的目錄定位，或解析為絕對路徑；不得依賴未指定的目前工作目錄。

## Good Example

- SOP 指出執行目錄、腳本與參數。

```markdown
1. `DELEGATE` 在本 Skill 目錄執行 `uv run --script scripts/build_index.py --input records.csv --output index.json`，建立索引。
```

## Bad Example

- 同一個步驟沒有腳本路徑與參數，無法照原設計執行。

```markdown
1. `DELEGATE` 執行 Python 腳本建立索引。
```

# Rule 3 - SOP 必須交代執行環境缺失與結果驗證

- 目標 SOP 必須指出 `uv` 不存在時，依 uv 官方安裝說明選擇目前平台的安裝方式，安裝後重新執行；安裝失敗時回報原因並停止該步驟。
- 目標 SOP 必須在執行腳本後檢查退出狀態，以及已確認設計要求的輸出或副作用。

## Good Example

- SOP 對缺少執行工具與索引產物都有明確處理。

情境：

1. `uv` 不存在時，SOP 指引執行者依 `https://docs.astral.sh/uv/getting-started/installation/` 安裝並重試。
2. 執行索引腳本後，SOP 檢查退出狀態為零，且 `index.json` 包含預期的識別碼。

## Bad Example

- 同一個 SOP 沒有處理缺少工具，也沒有驗證執行結果。

情境：

1. `uv` 不存在時，執行者直接略過索引步驟。
2. 執行索引腳本後，SOP 不檢查退出狀態或 `index.json`。
