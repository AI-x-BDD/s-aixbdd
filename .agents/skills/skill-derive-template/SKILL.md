# SOP

## Phase 1 -- 定位樣板抽取點

1. `READ` 使用者需求、目標 Skill 的 `SKILL.md`，以及指定步驟已使用的既有樣板組（若有）。
2. `CHECK` 使用者或呼叫者指定的 Phase 與步驟可在目標 SOP 中唯一定位；無法唯一定位時，停止並請指定者補充。
3. `READ` 分析指定步驟時，讀取 `rules/樣板抽取分析-格式規範.md` 的所有 Rule，建立樣板抽取分析檢查清單。
4. `THINK` 依已載入的樣板抽取分析檢查清單，分析指定步驟的輸入、產出檔案、格式要求與完成條件，確定樣板組的用途、骨架、範例及第一個依賴樣板的步驟；呼叫者提供經使用者確認的工程藍圖時，以該工作項內容作為樣板組設計，並以樣板抽取分析檢查清單驗證該內容，不另行設計。
5. `CHECK` 逐條驗證樣板抽取分析檢查清單；未通過時修正樣板組設計與載入位置。

完成條件：樣板抽取分析檢查清單均已通過，且已確定目標步驟、樣板組設計與按需載入位置。

## Phase 2 -- 提出 Before／After

1. `WRITE` 整理原始 SOP 片段、修改後 SOP 片段，以及預計新增或調整的骨架、範例與填位符號，作為 Before／After；呼叫者未提供工程藍圖時，向使用者展示 Before／After。
2. `CHECK` 呼叫者已提供經使用者確認的工程藍圖時，比對 Before／After 是否與工程藍圖中該工作項的內容及 To-Be SOP 一致：一致時視為已確認，不一致時向呼叫者回報差異並停止執行；未提供工程藍圖時檢查使用者回覆，要求修改時返回 Phase 1，未明確確認時停止執行。

完成條件：使用者已明確確認 Before／After 與樣板組設計，或兩者與已確認的工程藍圖一致。

## Phase 3 -- 寫入與驗證

1. `READ` 委派樣板組與 SOP 寫入時，讀取 `rules/樣板組委派-格式規範.md` 的所有 Rule，建立樣板組委派檢查清單。
2. `CHECK` 已確認的提案符合樣板組委派檢查清單；未通過時返回 Phase 2。
3. `DELEGATE` 依已確認的提案與樣板組委派檢查清單，使用 `skill-form-template` 建立或更新骨架與範例。
4. `DELEGATE` 依已確認的 After 與樣板組委派檢查清單，使用 `skill-form-sop` 更新目標 `SKILL.md`，在第一個依賴步驟前的同一個 `READ` 步驟明列骨架與範例兩個相對路徑。
5. `CHECK` 骨架與範例均存在、目標 SOP 同時載入兩個路徑，實際變更符合已確認的 Before／After 與樣板組委派檢查清單，原有流程目的與順序未被非必要改變，且受影響的 Skill 通過適用驗證。

完成條件：樣板組委派檢查清單已通過，骨架、範例與 SOP 載入步驟均符合已確認的提案，且所有適用驗證均已通過。
