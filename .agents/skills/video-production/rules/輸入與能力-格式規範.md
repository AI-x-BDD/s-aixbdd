# Rule 1 - 從來源建立理解目標

- 必須先讀指定素材與既有決策，把來源事實、觀眾假設、美術裁量分開；為各段確定觀眾應理解的關係或變化。
- 必須辨識提案、製作、修正與重建的授權，以及內容、旁白、片長、品牌和聲音限制；只詢問會影響製作且現有來源無法回答的問題。
- 必須將章節、物件、配色、幕數及長度從本片素材推導；不得將上一片的個案數字或本機絕對路徑當成新片規則。

## Good Example

先從來源確定理解目標與限制，才決定畫面。

1. 新素材說明借閱逾期：目標是理解通知如何交給借閱者；三幕是本片設計選擇。
2. 既定旁白不可改；只調整能配合該音訊的畫面。

## Bad Example

以舊片習慣取代當次來源與已知資料。

1. 未讀新素材，就沿用上一片九幕和深色背景。
2. 來源已寫觀眾是新手，仍要求使用者再提供設計術語。

# Rule 2 - 依賴必須能定位並合法取得

- 必須隨工具包攜帶 `style-library/` 與固定版 `.agents/skills/huashu-art-motion/`；先以 `scripts/style_library.py check --library style-library` 檢查目錄、來源及實際預覽。缺庫、改版或證據不符必須阻擋，不得臨時搜尋或憑空捏造風格代替。
- 第三方原文保持原樣；本專案固定版本優先於上游自動更新／版本檢查指令，禁止在製作途中執行其自動更新。更新風格庫須作獨立、有授權的依賴變更並重建證據。
- 新片設定必須啟用 `style_library_required = true`，指定工具根目錄相對的 `style_library` 與本片 source_root 相對的 `style_selection`；選用 JSON 的 choices 必須記錄可選 ID、content_reason、adaptation，catalog_sha256 必須符合當前目錄。prepare、render、review、deliver 都核對。未帶欄位必須報錯；歷史重建或隔離工程測試須在設定中明列 false 與 legacy_style_reason，記錄於 prepare 證據，不得供新片規避。
- 必須從專案指引定位 videos 工具根目錄，讀取其 README 與第三方來源清單，將 Skill、專案工具、第三方依賴、個案素材分開；搬移時必須帶齊工具包、鎖檔及合法依賴。
- 必須依來源清單的精確目錄載入 storyboard、presentation-design-editorial、motion-art-direction；同名 presentation-design 不得只按名稱委派。
- 必須查核必要第三方的固定 revision、原文雜湊及可用授權；授權不明原文不得加入可攜包。官方 Remotion Skill 按固定版下載及驗證，保留其來源和授權狀態。
- 可以在具備可用授權證據時使用診斷版 presentation-design 輔助；未取得時必須由主代理依本 Skill 評審，不能因此跳過評審或阻擋基本製作。
- 必須將目前支援平台寫為 macOS；其他平台及其他機器重建未實跑時必須標明未驗證。

## Good Example

依精確來源與授權取得資源，並交代搬移缺項。

1. 根據 videos/.agents/skills/來源.json 載入 editorial 目錄；官方 Skill 留在固定版快取。
2. 搬移包另帶新素材與模型路徑；缺工具時指出具體缺項。

## Bad Example

將依賴或授權缺口包裝成可直接使用。

1. 只複製 Skill 資料夾，就聲稱能在任意電腦編碼。
2. 把無授權證據的第三方原文複製進新 Skill。

# Rule 3 - 能力宣告必須來自當次實測

- 必須列出當次可用的動畫渲染、配音、視覺輸入、音訊輸入，執行小段實測並記錄工具、日期、輸入範圍和結果。
- 必須分清直接聽看、音訊分析或 ASR、靜態抽幀、播放命令；抽幀、ASR、音訊雜湊與播放成功不得宣稱為 AI 直接連續聽看。
- 必須依本次工具實測判定能力；目前工具不支援 AI 直接連續聽看影片，在能力紀錄說明一次，不列為待辦、交付固定欄位或反覆附註。後續只有接入新工具時才重查能力，不得以未來可能性宣稱現況。

## Good Example

聲稱的能力只涵蓋當次工具確實處理的輸入。

1. 成功編碼並解碼小段；可檢視畫格，能力紀錄標示目前不支援直接連續聽看，交付只列實際執行的檢查。
2. ASR 得到字詞時間，只支持對齊分析。

## Bad Example

將播放或舊能力紀錄誤當成當次直接理解。

1. 執行 open 影片.mp4 後宣稱 AI 已看完整片。
2. 沿用昨天的能力文字，未測試本次工具。

# Rule 4 - 配音與實際時間必須相符

- 必須優先沿用已確認原音及剪接決策；新稿依實際可用且已授權的服務產生配音，未有正式聲音時可以用本機預覽語音並明示差異。
- 必須對新音訊使用現有 align.py 的實際對齊能力，明確指定模型路徑，保存模型來源 revision 或可辨識來源與檔案雜湊；缺模型時必須列明取得方式、大小及阻擋，不能以估時計時宣稱已對齊。
- 必須核對音訊、稿件與對齊的來源一致；只改畫面可以保留對齊，改稿或音訊時必須重對齊。字元匹配率與內插結果不得宣稱為逐句聽審。
- 必須記錄正式或預覽聲音、轉碼或複製處理與尚未驗證的聽感；付費、上傳及變動決策依既有授權處理。

## Good Example

沿用聲音時核對來源，新聲音則實際對齊並標明用途。

1. 沿用借閱通知正式音檔，只改圖解；音檔與稿件雜湊相符所以保留對齊。
2. 以 say 產生新主題預覽，使用指定本機模型重新辨識並匹配時間。

## Bad Example

改稿後使用舊時間，或把預覽聲音標成正式驗收。

1. 改旁白文字後沿用舊對齊，再按照字數平均分時間。
2. 沒有正式配音服務，卻把系統預覽音標為已驗收的正式聲音。
