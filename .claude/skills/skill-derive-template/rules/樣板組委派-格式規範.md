# Rule 1 - 委派內容必須對應已確認提案

- 委派 `skill-form-template` 時，必須指定已確認的骨架與範例路徑、目標格式、固定結構、填位符號及範例值。
- 委派內容不得加入、刪除或改寫未經確認的樣板要求。

## Good Example

- 委派內容完整指定兩個檔案與已確認的填位符號對應。

情境：

1. 已確認的骨架：`templates/class-diagram.mmd`，使用 `{{CLASS_NAME}}` 與 `{{METHOD_NAME}}`。
2. 已確認的範例：`templates/class-diagram.example.mmd`，使用 `Order` 與 `submit`。
3. 委派 `skill-form-template` 依上述設計建立這兩個檔案。

## Bad Example

- 委派只指定骨架，並授權自行補充未確認的內容。

情境：

1. 已確認的提案包含骨架與範例兩個檔案。
2. 委派 `skill-form-template` 建立 `templates/class-diagram.mmd`，自行決定其他內容。

# Rule 2 - SOP 委派必須保留雙檔載入

- 委派 `skill-form-sop` 時，已確認的 After 必須包含骨架與範例兩個相對路徑。
- 兩個路徑必須只出現在實際載入檔案的 `READ` 步驟；後續步驟必須使用該步驟命名的載入結果。
- `READ` 步驟必須在第一個依賴樣板組的步驟前按需執行，且原有流程目的與順序必須保留。

## Good Example

- After 在 `READ` 中載入兩個檔案，`WRITE` 使用具名結果。

```markdown
1. `READ` 產生類別圖時，讀取 `templates/class-diagram.mmd` 與 `templates/class-diagram.example.mmd`，建立類別圖樣板組。
2. `WRITE` 依已載入的類別圖樣板組產生類別圖。
```

## Bad Example

- After 只載入骨架，且在 `WRITE` 中重複使用路徑，範例未被載入。

```markdown
1. `READ` 讀取 `templates/class-diagram.mmd`。
2. `WRITE` 依 `templates/class-diagram.mmd` 產生類別圖。
```
