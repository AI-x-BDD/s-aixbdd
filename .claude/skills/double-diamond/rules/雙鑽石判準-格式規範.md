# Rule 1 - 保留兩次發散收斂及非線性模型

- 說明或運用雙鑽石時，必須保留其目的：防止太早認定問題、太早愛上某個解法。
- 必須依下列兩個空間與四階段理解模型。

```text
第一鑽石  Problem Space   找對事情（Design the right thing）
  Discover  發散：挑戰「我們以為的問題」
  Define    收斂：根據證據決定真正要解什麼
第二鑽石  Solution Space  把事情做好（Design the thing right）
  Develop   發散：展開多個方案，做便宜的驗證
  Deliver   收斂：用測試與證據留下有效方案
```

- Develop 不得被解讀為「開始寫 code」；它是發展多種可能方案，可以包括 sketch、prototype、技術 spike、小型 PoC。
- Deliver 不得被解讀為只有「deploy」；它是驗證、淘汰、改善後找到真的可行的方案。
- Double Diamond 是描述設計流程的模型，不是規格或逐步 SOP；不得把本 Skill 的工作步驟當作官方強制程序。
- 流程不是線性的，任何階段都可以因為新的學習回到前面，不得當成做完不能回頭的 Waterfall。

## Good Example

以兩次發散收斂理解工作，允許證據改變原判斷。

- 情境：團隊比較三種客服操作原型，測試發現真正障礙是資料取得方式。
- 判斷：Develop 是展開與試探方案；新證據顯示問題可能定義錯誤，可以回 Discover／Define。
- Deliver：透過測試淘汰或改善方案，不因完成部署就視為驗證成功。

## Bad Example

相同情境把模型當不可回頭的開發階段。

- 情境：原型測試發現真正障礙是資料取得方式。
- 判斷：已進 Develop，所以只能繼續寫正式程式，禁止回 Define。
- Deliver：完成 deploy 就算全部完成。

# Rule 2 - 區分來源層級並保留四個設計原則

- 回答時必須區分說法來源，不得把實務判斷說成官方規定。

| 層級 | 來源或內容 |
| ---- | ---- |
| 官方定義／官方原則 | Design Council：Framework for Innovation、The Double Diamond、History |
| 業界慣例 | NN/g、IDEO 等，例如 Desirable／Viable／Feasible、Decision Gate |
| 實務判斷 | 例如「研究何時算夠」 |

- 說明官方 Design Principles 時，必須保留以下四項：Put people first、Communicate visually and inclusively、Collaborate and co-create、Iterate, iterate, iterate。

## Good Example

把官方原則與其他判斷分開歸屬。

- 情境：團隊詢問以人為本、三面向可行性及研究停止的來源。
- 回答：Design Council 的四原則是以人為本、視覺且包容地溝通、協作共創、持續迭代；Desirable／Viable／Feasible 是 NN/g 檢查視角；研究何時足夠是實務判斷。

## Bad Example

相同情境把所有內容合稱官方強制規則，並漏掉原則。

- 情境：團隊詢問原則與來源。
- 回答：Design Council 只有以人為本一條原則，三面向與固定研究門檻都是官方強制規定。

# Rule 3 - 正確說明與 Design Thinking 及 Agile 的關係

- 比較 Design Thinking 時，應說明它是較大的思考哲學；Double Diamond 是把設計流程視覺化的一種方法。IDEO 的 Creating choices → Making choices 對應發散 → 收斂。
- 比較 Agile 時，應說明 Double Diamond 回答「應該做什麼」，Agile 回答「怎麼快速、持續把東西做好」。
- 可以以下列方式說明實務接法，不得冒充官方唯一流程：Discover／Define → Product Backlog → Develop／Deliver → Sprint → Feedback → 重新 Discover。

## Good Example

說明定位與可搭配方式，而不是互斥選擇。

- 情境：Scrum 團隊擔心使用 Double Diamond 就不能繼續迭代。
- 回答：可以把 Discover／Define 的學習帶入 Backlog，於迭代中試驗與收集回饋；這是一種實務接法。Design Thinking 提供較大的思考脈絡，Double Diamond 將發散收斂視覺化。

## Bad Example

相同情境把兩者說成互斥，並捏造唯一順序。

- 情境：Scrum 團隊詢問能否搭配 Double Diamond。
- 回答：Double Diamond 就是 Design Thinking 的全部，採用後不能用 Agile；官方要求四階段全部做完才能開始任何 Sprint。
