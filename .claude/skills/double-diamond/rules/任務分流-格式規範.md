# Rule 1 - 先判斷不確定性，再決定從哪裡著手

- 必須先問「現在還有什麼不知道」，而不是先問「現在在哪一階段」。
- 應依最大未知使用下列分流；已明確的情境及例外依本檔 Rule 2 判斷。

| 不確定性 | 對應方向 |
| ---- | ---- |
| 問題、原因、解法、驗證方式都已明確 | 直接做／壓縮流程 |
| 不知道真正問題 | Discover |
| 有很多問題，不知道先做哪個 | Define |
| 問題清楚，不知道怎麼解 | Develop |
| 已有解法，不知道是否有效 | Deliver／Test |

- 碰到需求應使用日常四問檢查，不需要每次畫兩顆鑽石。

| 問題 | 檢查 |
| ---- | ---- |
| Problem | 我現在講的是問題，還是其實已經是解法？「需要加 Tab」是解法。 |
| Evidence | 這是證據，還是某個人猜的？「老闆覺得大家不會用」是 Hypothesis。 |
| Alternatives | 是不是只考慮一個方案？是的話，第二鑽石沒有展開。 |
| Validation | 拿什麼證明這個方案成功？「大家覺得不錯」代表 Deliver 還沒完成。 |

- 證據與假設必須分開寫，不得把 stakeholder 的說法當成已驗證的 fact。
- 問題不明確、利害關係人多、解法成本高，或需求很可能已經指定解法時，應針對不確定性深入探索；例如留存降低、重寫系統、支付流程、大型改版或「新增 AI Chatbot」。

## Good Example

先檢查未知，不把指定工具與主管的感覺當問題證據。

- 情境：主管說「使用者不會用報表，所以新增教學影片」，尚無操作觀察。
- 判斷：教學影片是解法，「不會用」是待驗證假設；最大的未知是使用者在哪裡受阻，先 Discover。
- 若已有影片而不知道能否改善任務完成率，下一步是 Deliver／Test，不因有產出就宣稱成功。

## Bad Example

相同情境直接接受指定解法；已有產出便跳過驗證。

- 情境：主管要求新增教學影片，尚無操作觀察。
- 判斷：已確認使用者缺影片，立刻製作。
- 影片完成後主管覺得好看，宣布改善成功。

# Rule 2 - 依已知條件與急迫性壓縮流程

- 問題、原因、解法、驗證都已知時，可以直接做／壓縮流程；例如 padding 寫錯、timeout 5 秒改 10 秒。不得為了看起來有流程而強跑 workshop。
- 緊急事故，例如 production 全掛、SQL injection，必須先建議 contain → patch → deploy → verify，事後再 incident review，那時才進入 Discover root cause。
- 法規要求的第一鑽石可以很短；第二鑽石的 UI 怎麼放、怎麼減少摩擦仍有價值。
- 成熟問題、團隊領域知識充足時，應壓縮流程，而不是完全拿掉；這是 NN/g 觀點。

## Good Example

已知問題不重啟全面研究；事故先恢復；已定義務保留呈現探索。

- 小修正：padding 單位誤植且修正與畫面驗證皆已知，直接修與驗證。
- 事故：服務遭受 SQL injection，先止血、修補、部署與驗證，恢復後追查 review 與測試為何漏掉。
- 法規：義務已確定，縮短是否需要做的討論，仍比較說明放置方式與使用摩擦。
- 成熟問題：沿用團隊已有證據，保留必要驗證，壓縮研究。

## Bad Example

相同條件卻無條件要求完整流程，或把壓縮誤當免驗證。

- 小修正：已確認 padding 單位誤植，仍要求完整 workshop 才能修。
- 事故：SQL injection 正持續發生，先排訪談再決定是否止血。
- 法規：義務已確定，仍花時間探索是否可以不遵守，完全不看呈現摩擦。
- 成熟問題：因團隊熟悉就省略所有驗證。

# Rule 3 - 研究是否足夠取決於決策未知

- 判斷研究何時足夠時，必須標明這是實務判斷，非官方規定。
- 應看「最大的未知是否已經小到足以做決策」；繼續研究不太可能改變決策時就收斂。
- 不得用固定訪談人數宣稱是否符合 Double Diamond，例如「沒做五次訪談所以違反 Double Diamond」。

## Good Example

依證據是否還會影響決策收斂，而不是湊數。

- 情境：客服回報與操作資料已反覆支持相同問題，新研究不再改變優先順序。
- 判斷：可以收斂並驗證方案；這是依目前未知程度作的實務判斷，若新證據出現仍可回頭。

## Bad Example

相同證據下用任意人數冒充官方規定。

- 情境：新研究不再改變優先順序。
- 判斷：官方要求至少五次訪談，少一次就違反 Double Diamond，必須繼續研究。
