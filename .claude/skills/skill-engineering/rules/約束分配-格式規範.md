# Rule 1 - 每條約束只能有一個存放位置

- 每條約束必須以 `C1`、`C2` 連續編號，並只指定一個存放位置。
- 約束分配表必須涵蓋 To-Be 中所有步驟內文、RuleFile、樣板組與腳本所表達的約束，包含本次沒有修改的既有約束。
- 存放位置判斷不同的要求，必須拆成不同約束。
- 同一條約束不得同時寫在 SOP 步驟內文、RuleFile、樣板組或腳本中的兩處以上。
- SOP 步驟可以引用存放約束的部位載入結果，但不得重述該約束的內容。
- 範例可以示範約束，但不得與存放位置中的約束互相矛盾。
- frontmatter 的 `description` 與完成條件可以概述 Skill 或 Phase 的結果，`description` 也可以列出 skill-form-description 要求的觸發關鍵字；兩者不視為存放位置，但不得重述約束的判斷細節。
- skill-form-* 或 skill-derive-* 的規則要求每個相關步驟都必須包含的固定寫法，例如執行腳本時缺少 `uv` 的處理方式，不視為重複的約束。

## Good Example

### Example 1

- 「兩個頂層 Section」只由樣板組保證，步驟只引用載入結果。

| 編號 | 約束                                               | 存放位置         |
| ---- | -------------------------------------------------- | ---------------- |
| C2   | 提案檔依序包含「類別圖」與「設計說明與實作順序」   | 類別圖提案樣板組 |

```markdown
11. `WRITE` 依已載入的類別圖輸出檢查清單與「類別圖提案樣板組」，將完整 Markdown 類別圖提案檔寫入指定路徑。
```

### Example 2

- 約束分配表同時列出本次新增與沒有修改的既有約束，每條只有一個存放位置。

| 編號 | 約束 | 存放位置 |
| ---- | ---- | -------- |
| C1 | 報告結尾列出資料來源（本次新增） | `rules/報告內容-格式規範.md` Rule 3 |
| C2 | 報告依序包含摘要、分析與結論三個段落（既有，不變） | 報告樣板組 |
| C3 | 報告中的數字必須標明單位（既有，不變） | `rules/報告內容-格式規範.md` Rule 1 |

### Example 3

- 錯誤訊息 RuleFile 的 Rule 1 同時要求回應欄位順序與訊息內容；欄位順序由錯誤回應樣板組固定，訊息內容需要判斷，兩者拆成不同約束，Rule 1 的欄位順序條列因此可以對應到樣板組而被發現重複。

| 編號 | 約束 | 存放位置 |
| ---- | ---- | -------- |
| C4 | 錯誤回應依序包含 `code` 與 `message` 欄位 | 錯誤回應樣板組 |
| C5 | `message` 必須指出失敗欄位 | `rules/API-錯誤訊息-格式規範.md` Rule 1 |

## Bad Example

### Example 1

- 同一個結構同時寫在樣板組與多個步驟中，修改結構時必須同步多處。

```markdown
11. `WRITE` 依「類別圖提案樣板組」寫入提案檔；第一個頂層 Section 放置 Mermaid 類別圖，第二個頂層 Section 放置設計說明與實作順序。
12. `CHECK` 確認兩個頂層 Section 結構。
```

### Example 2

- 同一情境中，約束分配表只列出本次新增的約束；既有的 C2 標為「不變」就沒有檢查，它同時存放在 RuleFile 與樣板組，重複沒有被發現。

| 編號 | 約束 | 存放位置 |
| ---- | ---- | -------- |
| C1 | 報告結尾列出資料來源（本次新增） | `rules/報告內容-格式規範.md` Rule 3 |
| C2 | 報告依序包含摘要、分析與結論三個段落（既有，不變） | `rules/報告內容-格式規範.md` Rule 2 與報告樣板組 |

### Example 3

- 同一情境中，Rule 1 的兩項要求被打包成一條約束，依需要判斷的訊息內容整條分配給 RuleFile；樣板已固定的欄位順序跟著被保留，重複沒有被發現。

| 編號 | 約束 | 存放位置 |
| ---- | ---- | -------- |
| C4 | 錯誤回應依序包含 `code` 與 `message` 欄位，`message` 必須指出失敗欄位 | `rules/API-錯誤訊息-格式規範.md` Rule 1 |

# Rule 2 - 存放位置必須依強制力順序選擇

- 屬於執行順序、分支、使用者確認或 Phase 轉移的約束，必須留在 SOP 流程。
- 其他約束必須依下表由上而下，選擇第一個符合條件的存放位置。
- 不符合腳本、樣板組或 RuleFile 條件的約束必須留在所屬步驟的內文，不得為其建立新的部位。
- 既有工具的單一命令即可完成的工作，必須把該命令寫在步驟內文，不得另建腳本包裝。
- 腳本列的條件指工作本身可由程式完成；只為驗證樣板組已規範之結構而建立的腳本，視為重複存放。
- 每條約束必須寫出選擇該存放位置的理由，以及不選擇較高順序位置的原因。

| 順序 | 存放位置 | 條件                                                   |
| ---- | -------- | ------------------------------------------------------ |
| 1    | 腳本     | 輸入與輸出明確、可以重複執行，且結果可由程式判斷       |
| 2    | 樣板組   | 約束的是某一份產出檔案的整體結構                       |
| 3    | RuleFile | 持續適用且需要判斷，需要正反例才能一致執行             |
| 4    | 步驟內文 | 只屬於單一步驟，一句話即可完整表達，且不需要正反例     |

## Good Example

- 由上而下檢查條件，說明為何不選擇較高順序的位置。

| 編號 | 約束                       | 存放位置 | 理由                                                                                         |
| ---- | -------------------------- | -------- | -------------------------------------------------------------------------------------------- |
| C1   | 每個類別標示變更類型       | RuleFile | 判斷新增、修改或既有需要設計語意，腳本無法判斷；骨架以區塊填位符號產生類別，樣板無法逐類別保證；需要正反例 |

## Bad Example

- 樣板組已能保證的整體結構被寫成 RuleFile，且沒有說明選擇理由。

| 編號 | 約束                                   | 存放位置 | 理由 |
| ---- | -------------------------------------- | -------- | ---- |
| C2   | 提案檔依序包含兩個頂層 Section         | RuleFile | 無   |

# Rule 3 - 同主題約束必須集中在同一部位

- 同一主題的約束必須放在同一個 RuleFile；目標 Skill 已有同主題 RuleFile 時，必須擴充該檔案，不得新增檔案。
- 同一種產出格式只能有一組樣板；已有對應樣板組時，必須修改既有樣板組。
- 不同主題的約束不得為了減少檔案數而合併到同一個 RuleFile。

## Good Example

- 變更標示屬於類別圖輸出主題，因此擴充既有的類別圖輸出 RuleFile。

| 編號 | 約束                 | 存放位置                                 |
| ---- | -------------------- | ---------------------------------------- |
| C1   | 每個類別標示變更類型 | 擴充 `rules/類別圖輸出-格式規範.md` Rule 2 |

## Bad Example

- 同主題的約束被拆成只有一條 Rule 的新檔案。

| 編號 | 約束                 | 存放位置                              |
| ---- | -------------------- | ------------------------------------- |
| C1   | 每個類別標示變更類型 | 新增 `rules/類別狀態標示-格式規範.md` |
