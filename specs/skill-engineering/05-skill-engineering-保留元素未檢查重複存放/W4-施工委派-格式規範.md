# Rule 1 - 施工類型必須交給對應的執行者

- 每個施工工作項必須依下表交給對應的執行者。
- 新增部位不得直接交給 `skill-form-rule`、`skill-form-template` 或 `skill-form-script`；必須交給對應的 `skill-derive-*`，由其同時建立部位與載入步驟。
- 刪除整個部位檔案時，必須同時由 SOP 施工移除該部位的載入或執行步驟。

| 施工類型                           | 執行者                                                            |
| ---------------------------------- | ----------------------------------------------------------------- |
| 刪除整個部位檔案                   | `skill-engineering` 直接刪除                                      |
| 建立或修改 frontmatter             | `skill-form-description`                                          |
| 建立或修改 SOP                     | `skill-form-sop`                                                  |
| 修改既有部位內容，不改變載入步驟   | `skill-form-rule`、`skill-form-template` 或 `skill-form-script`   |
| 新增部位，或改變部位的載入步驟     | `skill-derive-rule`、`skill-derive-template` 或 `skill-derive-script` |

## Good Example

- 修改既有 Rule 的內容交給 `skill-form-rule`，為步驟新增樣板組交給 `skill-derive-template`。

| 工作項 | 施工類型                 | 執行者                  |
| ------ | ------------------------ | ----------------------- |
| W2     | 修改既有 Rule 2 的內容   | `skill-form-rule`       |
| W4     | 為 P1-11 新增樣板組      | `skill-derive-template` |

## Bad Example

- 新增樣板組直接交給 `skill-form-template`，沒有任何步驟載入新樣板組。

| 工作項 | 施工類型            | 執行者                |
| ------ | ------------------- | --------------------- |
| W4     | 為 P1-11 新增樣板組 | `skill-form-template` |

# Rule 2 - SOP 施工必須先寫入胖 SOP

- 交給 `skill-form-sop` 的 SOP 必須是胖 SOP：保留的既有載入步驟維持原樣，待抽取的約束先寫在所屬步驟的內文。
- 胖 SOP 不得出現尚未建立之部位的載入或執行步驟。
- 待抽取的工作與另一個不同的動作混在同一步驟時（例如類別設計與計畫編號），胖 SOP 必須先把待抽取的工作拆成獨立步驟，讓抽取工作項能唯一定位；多個部位規範同一個動作時不需拆分。
- 抽取工作項的 After 必須包含因抽取而需要調整的依賴步驟與完成條件，例如改為逐條驗證新檢查清單的 `CHECK` 步驟。
- 抽取完成後仍需修改、但不屬於任何抽取工作項的 SOP 內容，例如移除已不再使用的輸入，必須列為 SOP 收尾工作項。
- 所有施工工作項完成後，SOP 必須與工程藍圖的 To-Be SOP 一致。

## Good Example

- 胖 SOP 先把待抽取的錯誤訊息約束寫在步驟內文，`skill-derive-rule` 抽取後才出現載入步驟。

胖 SOP：

```markdown
3. `WRITE` 產生 API 錯誤訊息；錯誤訊息必須指出失敗欄位、收到的值與預期格式。
```

抽取後的 To-Be SOP：

```markdown
3. `READ` 產生錯誤訊息時，讀取 `rules/API-錯誤訊息-格式規範.md` 的所有 Rule，建立錯誤訊息檢查清單。
4. `WRITE` 依已載入的錯誤訊息檢查清單產生 API 錯誤訊息。
```

## Bad Example

- 直接寫入 To-Be SOP，載入一個尚未建立的 RuleFile；`skill-derive-rule` 也找不到待抽取的約束。

```markdown
3. `READ` 產生錯誤訊息時，讀取 `rules/API-錯誤訊息-格式規範.md` 的所有 Rule，建立錯誤訊息檢查清單。
4. `WRITE` 依已載入的錯誤訊息檢查清單產生 API 錯誤訊息。
```

# Rule 3 - 施工順序必須固定

- 施工工作項必須依刪除部位、frontmatter、胖 SOP、修改既有部位內容、抽取部位、SOP 收尾的順序執行。
- 同一步驟有多個抽取工作項時，必須依腳本、樣板組、RuleFile 的順序執行。
- 不同步驟的抽取工作項，必須從 SOP 中位置最後的步驟往前執行。

## Good Example

- 先完成 SOP 與既有部位修改，再由後往前抽取；同一步驟先抽腳本再抽 RuleFile。

| 順序 | 工作項 | 內容                         |
| ---- | ------ | ---------------------------- |
| 1    | W1     | 以 `skill-form-sop` 寫入胖 SOP |
| 2    | W2     | 修改既有 Rule 2              |
| 3    | W5     | 為 P2-3 抽取腳本             |
| 4    | W6     | 為 P2-3 抽取 RuleFile        |
| 5    | W7     | 為 P1-4 抽取樣板組           |

## Bad Example

- 先抽取前面的步驟，插入的載入步驟使後面步驟的位置改變；抽取也早於胖 SOP 寫入。

| 順序 | 工作項 | 內容                         |
| ---- | ------ | ---------------------------- |
| 1    | W7     | 為 P1-4 抽取樣板組           |
| 2    | W6     | 為 P2-3 抽取 RuleFile        |
| 3    | W1     | 以 `skill-form-sop` 寫入胖 SOP |

# Rule 4 - 委派內容必須是藍圖的對應段落

- 每次委派必須傳入工程藍圖「工作項內容」中對應工作項的完整內容，並說明該內容已經使用者確認。
- 委派的目標步驟必須以 Phase 標題、受控動詞與步驟內文的關鍵字定位，不得只使用步驟編號。
- 委派內容不得加入、刪除或改寫工程藍圖未記載的要求。

## Good Example

- 委派內容引用已確認的工作項，以步驟內文定位，並完整交付約束。

情境：

- 委派：依使用者已確認的工程藍圖工作項 W2，使用 `skill-form-rule` 修改 `class-diagram-planner` 的 `rules/類別圖輸出-格式規範.md` Rule 2，加入「每個類別必須以 annotation 標示 `<<new>>`、`<<modified>>` 或 `<<existing>>` 其中一種」，並依此更新 Good Example 與 Bad Example。

## Bad Example

- 委派只給步驟編號，並授權執行者自行補充未確認的規則。

情境：

- 委派：請 `skill-derive-rule` 幫 Phase 1 步驟 11 補一些適合的規則。

# Rule 5 - 施工差異必須回報而不是自行調整

- 被委派 Skill 回報與工程藍圖不一致，或其分析規則拒絕工作項時，必須停止後續施工並記錄差異。
- 停止時，已完成的工作項必須標記為「已完成」，其餘工作項維持「待施工」，重新施工時只執行「待施工」的工作項。
- 不得自行調整工程藍圖，也不得略過被拒絕的工作項。

## Good Example

- `skill-derive-template` 的分析規則拒絕工作項後，停止施工並只重新設計差異部分。

情境：

1. `skill-derive-template` 回報：P1-4 只約束檢查行為，沒有固定的產出檔案格式，不適合建立樣板組。
2. 停止後續施工，在工程藍圖記錄差異。
3. 回到重新設計，將該約束改為 RuleFile，並請使用者確認修改後的工作項。

## Bad Example

- 同一個拒絕被略過，其餘工作項繼續施工。

情境：

1. `skill-derive-template` 回報：P1-4 不適合建立樣板組。
2. 略過該工作項，繼續執行其餘工作項，並在最後回報「已完成」。
