# Rule 1 - 評審對象必須是實際編碼成片

- 必須檢查實際編碼 MP4，涵蓋全片各段解說中途、尾端、移動／形變／交棒／鏡頭過渡與所有豁免區間；週期抽幀不足時必須補語意風險時間點。
- 必須核對名稱、路徑、鏡頭、字幕、來源內容、焦點與停留目的；只看原稿、Studio 或物件落地畫面不能通過成片評審。
- 必須從編碼成片逐幀擷取每個切點前後的連續序列，範圍必須涵蓋動作收尾、核心穩定期與下一幕進場；高風險移動必須另涵蓋其起迄，逐項記下位置／方向變化、身份、落定、穩定閱讀時間及切換理由。孤立畫格、技術通過或自報動作時長不得代替序列觀察。
- 必須將序列觀察與實際語音時間對照，核對核心是否在對應詞句得到強調；只有逐幀圖像與時間資料時，必須限制為可觀察的切斷、跳位、可讀性及落定證據，不得宣稱已驗證連續聽感、動態舒適度或現場簡報效果。
- 必須從成片畫格確認字幕已燒錄且不遮內容；沒有字幕軌不能單獨證明字幕已燒錄。

## Good Example

以實際 MP4 的過渡與字幕畫格作判斷。

1. 成片在形變中途名稱消失，即使落地完整與技術檢查通過，仍判不通過。
2. 切點前後逐幀序列顯示手指已落定，主訊息保持到句末才換幕；另核對長字幕畫格。

## Bad Example

僅以原稿、落地畫面或串流資訊推定成片通過。

1. 只看切點前後各一張 PNG，沒有檢查尚在移動就消失的中間過程，仍說節奏通過。
2. ffprobe 沒有 subtitle stream 就認定燒錄成功。

# Rule 2 - 修正必須使來源與證據重新對齊

- 必須將問題定位到成片版本與時間，寫明可觀察現象、影響理解的原因、修法與複查觀察。
- 來源修改後必須重建並重新檢查受影響範圍及必要整體關聯；證據必須綁定新成片與來源，不得沿用舊抽幀冒充新片。
- 必須在交付前核對來源、成片、狀態與評審所指為同一版本；工具失敗時必須保留上一版並列明失敗。

## Good Example

修正後重新建置、取樣，並把觀察綁到新版本。

1. 5.2 秒標籤消失：修正透明度後重建，重新看 5.1、5.2、5.4 秒並綁新 MP4 SHA。
2. 字幕改動後重新輸出、抽幀及填寫新的評審版本。

## Bad Example

用舊影片或舊抽幀代表尚未驗證的修正。

1. 改了動畫，但評審仍引用舊影片的截圖。
2. 建置失敗後仍把舊正式片說成已包含本輪修正。

# Rule 3 - 五種結果必須分別記錄

- 必須分別記錄自動技術與狀態檢查、靜態畫格評審、音訊分析、直接連續聽看、使用者驗收的結果與證據。
- 必須區分通過、不通過與未驗證；未直接聽看時必須明示尚不能判斷的聽感、連續節奏或動態舒適度。
- 必須原樣保留使用者接受的範圍與版本；使用者接受不能改寫 AI 是否直接聽看的事實，也不得推定使用者觀看方式。

## Good Example

分開記錄各種證據與驗收，不推定未觀察的能力。

1. 技術及靜態畫格通過、音訊匹配完成、直接聽看未驗證、使用者接受此版。
2. 未接通音訊輸入，記音訊分析的方法與限制。

## Bad Example

把使用者接受或辨識結果轉寫成 AI 聽看結論。

1. 使用者說 OK，將直接聽看欄改成 AI 通過。
2. ASR 全文正確便宣稱聲畫節奏舒適。

# Rule 4 - 交付必須明示缺陷與能力限制

- 必須先修正漏項、提前失焦、錯對象、名稱消失、裁切、字幕遮擋、動作被無理由切斷、核心未落定與過期證據等可修正缺陷，再交付正式入口。
- 只有能力不足而無已知缺陷時，可以依授權提供帶限制的交付；必須具體列未驗證事項、證據範圍及使用者尚需判斷項目，不得聲稱完整聽看通過。
- 必須交付同一成片的播放與下載入口、可修改字幕來源、重建來源及命令，並保留使用者驗收狀態；工具缺失、建置失敗或缺少必要素材時不得宣稱完成。

## Good Example

修正已知缺陷後交付，能力限制則具體揭露。

1. 所有已知缺陷修正後交付；連續聽看列未驗證，明示已做哪些替代檢查。
2. FFmpeg 缺失，回報阻擋，不產生通過或完成標記。

## Bad Example

已知問題或必要工具缺失仍被標為完成。

1. 焦點已知提早消失，仍因 encode 成功直接發布。
2. 連線遮住名稱留待下次，卻標正式片已驗收。
