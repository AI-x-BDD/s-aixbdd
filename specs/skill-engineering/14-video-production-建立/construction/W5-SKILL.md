name: video-production
description: 將章節或主題素材製作成有旁白、燒錄字幕與動態敘事的影片，並交付成片與檢查紀錄。製作下一章影片、解說影片、video production、整體影片改版或修正聲畫焦點時使用；方向確認後在既有授權內完成製作。只做文字課程筆記改用 course-transcript-notes；只做 HTML 簡報改用 frontend-slides；只做動態美術諮詢改用 motion-art-direction。只重建已定版影片時依該片既有建置說明。
---

# SOP

## Phase 1 -- 確定內容與可用能力

1. `READ` 使用者需求、專案指引、指定章節素材、已有的影片設定與決策；續作時另讀現行交付紀錄。
2. `THINK` 確定本片識別、工具根目錄、本片目錄、本片設定與製作範圍；從授權區分提案、製作、修正與重建。
3. `THINK` 依下列要求判定缺少資料與依賴；無缺漏時進入步驟 6。 要求：必須先讀指定素材與既有決策，把來源事實、觀眾假設、美術裁量分開；為各段確定觀眾應理解的關係或變化。；必須辨識提案、製作、修正與重建的授權，以及內容、旁白、片長、品牌和聲音限制；只詢問會影響製作且現有來源無法回答的問題。；必須將章節、物件、配色、幕數及長度從本片素材推導；不得將上一片的個案數字或本機絕對路徑當成新片規則。；必須從專案指引定位 videos 工具根目錄，讀取其 README 與第三方來源清單，將 Skill、專案工具、第三方依賴、個案素材分開；搬移時必須帶齊工具包、鎖檔及合法依賴。；必須依來源清單的精確目錄載入 storyboard、presentation-design-editorial、motion-art-direction；同名 presentation-design 不得只按名稱委派。；必須查核必要第三方的固定 revision、原文雜湊及可用授權；授權不明原文不得加入可攜包。官方 Remotion Skill 按固定版下載及驗證，保留其來源和授權狀態。；可以在具備可用授權證據時使用診斷版 presentation-design 輔助；未取得時必須由主代理依本 Skill 評審，不能因此跳過評審或阻擋基本製作。；必須將目前支援平台寫為 macOS；其他平台及其他機器重建未實跑時必須標明未驗證。；必須列出當次可用的動畫渲染、配音、視覺輸入、音訊輸入及連續影音輸入，執行小段實測並記錄工具、日期、輸入範圍和結果。；必須分清直接聽看、音訊分析或 ASR、靜態抽幀、播放命令；抽幀、ASR、音訊雜湊與播放成功不得宣稱為 AI 直接連續聽看。；必須依本次工具實測判定能力；未接通時記未驗證及替代檢查，不得把永久缺乏或未來可用能力當現況。；必須優先沿用已確認原音及剪接決策；新稿依實際可用且已授權的服務產生配音，未有正式聲音時可以用本機預覽語音並明示差異。；必須對新音訊使用現有 align.py 的實際對齊能力，明確指定模型路徑，保存模型來源 revision 或可辨識來源與檔案雜湊；缺模型時必須列明取得方式、大小及阻擋，不能以估時計時宣稱已對齊。；必須核對音訊、稿件與對齊的來源一致；只改畫面可以保留對齊，改稿或音訊時必須重對齊。字元匹配率與內插結果不得宣稱為逐句聽審。；必須記錄正式或預覽聲音、轉碼或複製處理與尚未驗證的聽感；付費、上傳及變動決策依既有授權處理。
4. `WRITE` 只向使用者詢問影響製作且無法從來源取得的缺少資料。
5. `CHECK` 回覆是否補齊資料；補齊後回步驟 3，未回覆則停止依賴該答案的工作，無法提供時列阻擋。
6. `READ` 工具根目錄的 README、第三方來源清單及各實際指令的 help，建立「製作工具介面」。
7. `DELEGATE` 使用製作工具介面初始化本片工作區、安裝鎖定依賴並執行能力小段實測；音訊生成／對齊依本 Phase 已展開要求選定的方法執行。
8. `CHECK` 實測結果；缺少必要工具時回報具體原因並停止依賴步驟，可替代的能力按本 Phase 已展開要求記錄限制。
9. `WRITE` 依以下結構及本 Phase 已展開要求建立內容依據、能力結果、依賴清單與既有決策。 產出固定結構：素材、觀眾與理解目標、授權與限制、當次能力與依賴、候選、比較與推薦、確認與變更紀錄；欄位與固定結構：# {{TOPIC}} 製作計畫 /  / ## 素材、觀眾與理解目標 /  / - 素材與引用位置：{{SOURCES}} / - 觀眾／觀看情境：{{AUDIENCE}} / - 來源事實、觀眾假設、美術裁量：{{BASIS}} / - 各段理解目標與關係：{{GOALS}} / - 工具根目錄／本片設定／本片目錄：{{LOCATIONS}} /  / ## 授權與限制 /  / - 本次範圍：{{SCOPE}} / - 已確認且須沿用的內容、方向、原音、片長與其他限制：{{LOCKED}} / - 未知、缺漏及處理：{{UNKNOWNS}} /  / ## 當次能力與依賴 /  / - 測試日期與小段產物：{{CAPABILITY_PROBE}} /  / | 能力 | 工具／版本或精確路徑 | 實測與可支持的結論 | 限制／阻擋 | / | --- | --- | --- | --- | / {{CAPABILITIES}} /  / - 第三方來源、revision、原文雜湊與授權清單：{{DEPENDENCIES}} / - 配音正式／預覽、取得方式與授權：{{VOICE}} / - 對齊方法、明確模型路徑、來源／revision 與檔案雜湊：{{ALIGNMENT}} / - 音訊、內容與對齊關聯：{{AUDIO_PROVENANCE}} / - 搬移須攜帶與按需取得的項目：{{PORTABILITY}} /  / ## 候選、比較與推薦 /  / - 既有確認方向：{{EXISTING_DIRECTION}} / - 代表段與選擇理由：{{REPRESENTATIVE}} /  / | 方向 | 實際畫面／有聲預覽／跨幕縮圖 | 色彩與結構依據 | 實際觀察、反例與取捨 | / | --- | --- | --- | --- | / {{DIRECTIONS}} /  / - 比較的控制條件與限制：{{COMPARISON_LIMITS}} / - 推薦及理由：{{RECOMMENDATION}} / - 未呈現與未驗證：{{PREVIEW_LIMITS}} /  / ## 確認與變更紀錄 /  / | 時間 | 使用者原意與範圍 | 對應版本／產物 | 後續動作 | / | --- | --- | --- | --- | / {{DECISIONS}} / ；欄位隨本片素材填寫。

完成條件：素材、理解目標、授權與能力均有紀錄，必要依賴可用或已明列阻擋。

## Phase 2 -- 設計方向與代表預覽

1. `READ` 製作計畫與既有方向確認紀錄。
2. `CHECK` 已有確認方向時沿用並進入 Phase 3；尚未定方向時繼續。
3. `THINK` 依下列要求選取能檢驗內容關係與閱讀負荷的代表段落。 要求：必須從理解目標、內容關係、品牌限制與觀看情境推導方向；色相無來源依據時必須標為美術裁量，不得杜撰色彩心理或唯一正解。；未定方向時必須以同一代表內容製作至少兩個實質不同的實際畫面、有聲片段與跨幕縮圖，分別比較色彩、結構、焦點與節奏；色相效果比較應控制其他條件，無法控制時必須限制歸因。；代表片段必須是含配音與燒錄字幕的實際編碼影片，具備該段獨立契約，完成與正式片相同的技術守門及成片評審才可稱為「已通過代表段」；具體判準依本 Skill 成片評審規範，能力限制另記。；必須先檢視實際預覽、測試推薦可能失敗的情境，再說明推薦、取捨與未呈現項目；關鍵動態不得用色票或靜態淡化冒充。；已有確認方向時必須沿用；新主題必須重新確認適配理由，深色方案不是通用預設。；必須讓交棒、拆分、形變、回接與鏡頭移動對應內容中的責任移轉、組成、變化、關係或細節；不得只輪流變色或裝飾移動。；每段必須有明確觀看對象與觀看順序；刻意停留必須交代觀眾此時看什麼以及理解理由，解說未完時必須保留該對象與脈絡。；必須選擇能驗證內容關係、閱讀負荷與動作的代表段落，必須以實際代表片段檢驗所選內容關係、動作與閱讀負荷；已有方向時可以沿用方向，不得因舊片曾選某幕就固定照用。；必須先從內容與實際語音時間制定期望，再實作動畫；焦點契約必須獨立於繪圖 active，不能把程式當下亮什麼反推成正確答案。；必須覆蓋全片每段解說的完整起訖，列舉必須逐項對應具名物件與辨識文字，不能只亮群組。；應覆蓋完整解說；需要進場或交棒容許時必須逐段說明實際動作理由，並指定豁免過渡的成片取樣，不能沿用上一片固定寬限。；必須以實際旁白時間核對動作、閱讀與交接，未講完不得提前移走主焦點；短句必須檢查其中途與尾端。；必須讓移動、拆分與形變中的物件持續帶著可辨識名稱；不得等落地後才補字。；必須設計避開文字的傳遞路徑，鏡頭必須保留當前重點與必要脈絡；名稱、字幕與主要內容必須在實際大小下可讀。；必須預留字幕區並檢查文字長度、對比及遮擋；狀態可見或邊界合格不得替代實際畫格的可讀性判斷。
4. `DELEGATE` 依 Phase 1 依賴清單的精確路徑載入 storyboard、editorial presentation-design 與 motion-art-direction，提供內容依據與代表段落，取得候選方向及製作 brief。
5. `DELEGATE` 使用製作工具介面及固定版 Remotion Skill，在隔離的候選目錄製作代表預覽。
6. `CHECK` 依本 Phase 已展開要求檢視實際預覽；有問題回步驟 4 修正。
7. `WRITE` 將比較、推薦、能力限制及預覽連結寫入製作計畫，向使用者展示。
8. `CHECK` 使用者確認方向後記錄並進入 Phase 3；要求調整回步驟 3，未確認則停在候選。

完成條件：有可審閱的代表預覽與方向確認紀錄，或已沿用既有確認方向。

## Phase 3 -- 對齊旁白與逐幕分鏡

1. `READ` 已確認方向、內容來源、既有旁白／音訊、能力結果與製作計畫。
2. `THINK` 依下列要求形成旁白與動態設計，判定是否需要變更既有決策；不需變更時進入步驟 5。 要求：必須從理解目標、內容關係、品牌限制與觀看情境推導方向；色相無來源依據時必須標為美術裁量，不得杜撰色彩心理或唯一正解。；未定方向時必須以同一代表內容製作至少兩個實質不同的實際畫面、有聲片段與跨幕縮圖，分別比較色彩、結構、焦點與節奏；色相效果比較應控制其他條件，無法控制時必須限制歸因。；代表片段必須是含配音與燒錄字幕的實際編碼影片，具備該段獨立契約，完成與正式片相同的技術守門及成片評審才可稱為「已通過代表段」；具體判準依本 Skill 成片評審規範，能力限制另記。；必須先檢視實際預覽、測試推薦可能失敗的情境，再說明推薦、取捨與未呈現項目；關鍵動態不得用色票或靜態淡化冒充。；已有確認方向時必須沿用；新主題必須重新確認適配理由，深色方案不是通用預設。；必須讓交棒、拆分、形變、回接與鏡頭移動對應內容中的責任移轉、組成、變化、關係或細節；不得只輪流變色或裝飾移動。；每段必須有明確觀看對象與觀看順序；刻意停留必須交代觀眾此時看什麼以及理解理由，解說未完時必須保留該對象與脈絡。；必須選擇能驗證內容關係、閱讀負荷與動作的代表段落，必須以實際代表片段檢驗所選內容關係、動作與閱讀負荷；已有方向時可以沿用方向，不得因舊片曾選某幕就固定照用。；必須先從內容與實際語音時間制定期望，再實作動畫；焦點契約必須獨立於繪圖 active，不能把程式當下亮什麼反推成正確答案。；必須覆蓋全片每段解說的完整起訖，列舉必須逐項對應具名物件與辨識文字，不能只亮群組。；應覆蓋完整解說；需要進場或交棒容許時必須逐段說明實際動作理由，並指定豁免過渡的成片取樣，不能沿用上一片固定寬限。；必須以實際旁白時間核對動作、閱讀與交接，未講完不得提前移走主焦點；短句必須檢查其中途與尾端。；必須讓移動、拆分與形變中的物件持續帶著可辨識名稱；不得等落地後才補字。；必須設計避開文字的傳遞路徑，鏡頭必須保留當前重點與必要脈絡；名稱、字幕與主要內容必須在實際大小下可讀。；必須預留字幕區並檢查文字長度、對比及遮擋；狀態可見或邊界合格不得替代實際畫格的可讀性判斷。
3. `WRITE` 展示須變更的內容、原因、時間影響與替代方案。
4. `CHECK` 取得變更確認後繼續，未確認時停止受影響工作，要求調整時回步驟 2。
5. `DELEGATE` 依製作工具介面及已確認配音方式取得音訊與實際語音對齊；尚未正式配音時先產生明確標示的預覽語音。
6. `READ` `templates/分鏡與焦點.md` 與 `templates/分鏡與焦點.example.md`，載入「分鏡與焦點樣板組」。
7. `WRITE` 依分鏡與焦點樣板組、本片已展開分鏡要求及實際對齊，建立逐幕設計與獨立焦點契約。
8. `CHECK` 逐條核對本片已展開分鏡要求；時間負荷不符時回步驟 2 修正，涉及變更時通過對應確認步驟。

完成條件：每段解說都有可執行分鏡與時間契約，配音來源與未驗證事項可追溯。

## Phase 4 -- 製作、編碼與技術守門

1. `CHECK` 本次授權是否涵蓋正式製作；只有提案授權時展示已有預覽並停止正式製作。
2. `READ` 確認後分鏡、實際時間軸、本片設定與工具介面。
3. `DELEGATE` 使用本片 Remotion workspace 與固定版官方 Skill 實作場景、字幕及實際繪圖共用狀態；沿用已通過代表段，其他場景依各自分鏡製作。
4. `DELEGATE` 使用製作工具介面執行本片檢查與候選成片編碼。
5. `CHECK` 技術結果；失敗時保留既有正式交付並回步驟 3 修正；通過才進 Phase 5。

完成條件：候選完整成片及技術證據已產生，尚未以未評審版本取代正式交付。

## Phase 5 -- 成片評審、修正與交付

1. `READ` `rules/成片評審-格式規範.md` 的所有 Rule，建立「成片評審檢查清單」。
2. `CHECK` 依成片評審檢查清單核對實際成片與證據；能力允許時直接聽看，不能直接聽看時採已實測替代檢查並保留限制。
3. `THINK` 依成片評審檢查清單及本片理解目標，從實際畫格與時間點評審內容負荷與溝通問題；已有可用授權證據的診斷版 presentation-design 時才按精確路徑載入輔助。
4. `READ` `templates/評審與交付.md` 與 `templates/評審與交付.example.md`，載入「評審與交付樣板組」。
5. `WRITE` 依評審與交付樣板組記錄各面向結果、問題、修法與未驗證項目。
6. `CHECK` 有可修正缺陷時回 Phase 4，涉及既定決策變動時回 Phase 3；無缺陷時繼續。
7. `DELEGATE` 使用製作工具介面發布已評審成片到本片交付入口，保存來源、重建命令與相同影片雜湊。
8. `WRITE` 提供成片與簡短檢查結果；仍需使用者判斷的項目具體列出，已有使用者接受紀錄時沿用。
9. `CHECK` 使用者接受時記錄驗收與版本，回報問題時回相應製作階段，未回覆時記為待驗收，不重問既有方向與授權。

完成條件：交付入口、來源與證據對應同一版本；AI 檢查及使用者驗收分別有明確狀態。
