## 1. 使用者回報的問題

透過 `skill-form-sop` 寫入或修改的 SOP，步驟在讀取或委派部位之後，仍然重述部位已經規範的內容。所有寫 SOP 的路徑（`skill-engineering`、`skill-derive-rule`、`skill-derive-template`、`skill-derive-script`）最後都會經過 `skill-form-sop`，所以它是攔截這類重複的最後關卡。

## 2. 驗收條件

| 編號 | 驗收條件 | 來源 | 適用範圍 | 驗收情境 |
| ---- | -------- | ---- | -------- | -------- |
| E1 | `skill-form-sop` 寫入或修改 SOP 後，每個步驟都不重述該步驟讀取或委派之部位已規範的內容；呼叫者提供的已確認設計含有重述時，向呼叫者回報差異並停止 | 本次 | 通用 | S1、S2 |
| E2 | 只屬於單一步驟、沒有存放在任何部位的約束（例如胖 SOP 中待抽取的約束、計畫編號規則）仍可寫在步驟內文 | 既有 | 通用 | S2 |
| E3 | SOP 其餘格式要求不受影響：固定標題結構、受控動詞、完成條件、按需載入 | 既有 | 通用 | S1、S2 |
| E4 | 被 `skill-derive-rule`、`skill-derive-template`、`skill-derive-script`、`skill-engineering` 委派時，依呼叫者已確認的設計寫入 SOP，不另行設計 | 既有 | 通用 | S2、S3、S4 |

## 5. 根因

| 編號 | 位置 | 缺陷類型 | 說明與證據 | 反事實檢驗 |
| ---- | ---- | -------- | ---------- | ---------- |
| R1 | `skill-form-sop`／`rules/SOP-格式規範.md`／Rule 4 第 3 條 | 不可檢查 | 觀察：條列沒有定義步驟內文可以寫哪些內容，範例也沒有示範步驟重述部位的情況。推論：P2-2 無法判斷 P1-7 那種名詞清單是否違反（依據演練表） | 假設條列定義步驟只能寫控制平面，並禁止重述已讀取或委派的部位，而且範例示範「載入 rule 後又補充判準」：P2-2 可以逐步判斷，P1-7、P3-2 那類內容會被判為違反 |
| R2 | `skill-form-sop`／`SKILL.md`／P1-1 | 未載入 | 觀察：P1-1 只讀取目標 `SKILL.md`。推論：不讀取部位就無法判斷是否重述，例如 P1-2 的「預設 30」只有對照腳本介面才看得出來（依據 04 根因報告 R1） | 假設 P1-1 讀取 SOP 載入的 RuleFile、樣板組與委派腳本的介面說明：配合 R1，P2-2 可以比對出 04 的 R1–R4 |

## 6. 被排除的假設

| 假設 | 缺陷類型 | 排除依據 |
| ---- | -------- | -------- |
| H1：呼叫者（`skill-engineering`）交出的設計本身就有重述，下游無法修正 | 交接缺陷 | 觀察：`skill-form-sop` P1-3 規定設計不符合完成檢查清單時要回報差異並停止，所以下游本來就有攔截責任；它沒有攔截，原因是 R1、R2。上游的設計缺口另由 05 根因報告處理 |
| H2：`SOP-按需載入` Rule 1 已禁止重述 | 衝突 | 觀察：該 Rule 只禁止 `THINK`、`WRITE`、`CHECK` 重複參考檔的路徑，沒有禁止重述內容 |
| H3：個案偏好 | 非 Skill 問題 | 觀察：使用者要求所有經手的 Skill 都做到，E1 為通用 |

## 7. 影響範圍
