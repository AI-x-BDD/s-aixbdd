# 根因報告：plan-with-class-diagram－類別圖標示變更狀態

- 紀錄目錄：`specs/skill-engineering/01-plan-with-class-diagram-優化類別圖標示變更狀態/`
- 問題證據：使用者訊息（「類別圖上看不出哪些類別是新增、哪些是修改，雖然下方實作順序有寫」）；對話紀錄 `evidence/session-log.md`（觀察來源以「紀錄第 N 點」標示）；不滿意的產出物 `evidence/class-diagram-proposal.md`（以「產出檔第 N 行」標示）

## 1. 使用者回報的問題

使用 `plan-with-class-diagram` 規劃 java-web-framework 的 Request/Response Logging 後，類別圖上無法分辨哪些類別是本次新增、哪些是修改既有類別；實作順序雖有寫，但圖本身沒有標示。使用者預期類別圖本身就要標示變更狀態。

## 5. 根因

| 編號 | 位置 | 缺陷類型 | 說明與證據 | 反事實檢驗 |
| ---- | ---- | -------- | ---------- | ---------- |
| R1 | `plan-with-class-diagram`／`templates/class-diagram-proposal.md` 的圖本體佔位 `{{CLASS_DIAGRAM_BODY}}` 與設計說明佔位 `{{DESIGN_NOTES}}`，以及 `rules/類別圖輸出-格式規範.md` Rule 6 | 載體過弱 | 觀察：產出檔第 5–7 行三個類別無標記（E1 落差）。觀察：樣板的圖本體只有 `{{CLASS_DIAGRAM_BODY}}` 佔位，沒有標記的位置或格式；設計說明只有 `{{DESIGN_NOTES}}` 佔位。觀察：類別標記的要求只出現在 Rule 6 的文字與範例中，SKILL.md P1-12 只說「依檢查清單與樣板組建立」，沒有指定標記寫在哪裡，`scripts/` 中也沒有檢查標記的腳本。觀察：紀錄第 6 點顯示 AI 已判定各類別角色，規則也已在紀錄第 4 點載入。推論：角色資訊在寫入圖本體時遺失，而標記只靠文字規則交給 AI 判斷，符合 Rule 3「載體過弱」的定義（依據上述觀察）。 | 假設 P1-12 的圖本體與設計說明佔位已能承載每個類別的標記與樣式（且設計說明段要求同一組變更類型），從 P1-12 重新演練：E1 可滿足；E5 可滿足；E4 不受影響；E2 的落差不因此改變（見待確認事項 3）。 |
