## 5. 根因

缺陷類型表中沒有「重複存放」。本報告歸入「衝突」：同一判準有兩個來源，目前還沒有矛盾，但只改其中一處就會產生矛盾；修改方向「只保留一個來源」也和「衝突」相同。缺陷類型表的缺口由 `specs/skill-engineering/05-skill-engineering-保留元素未檢查重複存放/` 處理。

| 編號 | 位置 | 缺陷類型 | 說明與證據 | 反事實檢驗 |
| ---- | ---- | -------- | ---------- | ---------- |
| R1 | `plan-with-class-diagram`／`SKILL.md`／P1-2、P1-3 | 衝突（重複存放） | 觀察：P1-2 寫出預設 30，P1-3 要求傳入 `--max-classes`，腳本本身已經定義預設值 | P1-2 只選定入口類別、P1-3 不傳 `--max-classes` 時，上限只由腳本決定，E9 仍然滿足 |
| R2 | 同檔 P1-4 | 衝突（重複存放） | 觀察：「包含入口類別」「未超過上限」都由腳本的退出狀態與迴圈保證 | 只檢查退出狀態與 JSON 格式時，腳本仍會在找不到入口時失敗，E9 仍然滿足 |
| R3 | 同檔 P1-7 | 衝突（重複存放） | 觀察：名詞清單逐項對應 `類別設計` Rule 1–4 | 改為「設計類別與實作順序」後，判準仍由類別設計檢查清單提供，P1-8 逐條驗證，E6 仍然滿足 |
